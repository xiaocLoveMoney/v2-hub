| 3x-ui 接口随版本变化 | 新版本契约测试失败 | 支持基线固定在快照版本（Ruling-7），升级时先拉快照跑契约测试 |
| 禁用 client 触发 Xray 重启影响在线用户 | 批量禁用时节点短暂断连 | 对账器合并批量操作，并限制每台面板的重启频率 |
| 服务端链式改坏面板 Xray 配置 | 入口节点 Xray 启动失败 | 改前备份、只动 `hub-` 前缀条目、失败自动回滚（M7）；用户出口字段白名单与失败隔离（M9） |
| 用户借服务端链式访问服务器内网或让流量成环 | 用户出口地址是内网 / 平台自己的服务器 | 只许公网地址、域名解析后固定 IP、防环校验、写操作频控（Ruling-48、Ruling-49） |
| 用户借延迟测试让面板去探测内网或刷爆面板 | 测试目标是内网地址；同一用户短时间大量测试 | 用户出口先过服务端链式的地址限制并用固定 IP；每用户频控、同服务器互斥；用户侧不回显错误原文（Ruling-52） |
| 平台被攻破后托管主机的 root 权限一并暴露 | 审计里出现异常的 `host_task.create`；主机上出现非平台发起的登录 | SSH 凭据加密存、只写不读；只有固定动作、没有任意命令；`host:write` 单独授权；主机密钥固定防中间人（Ruling-68）。建议给平台单独的密钥对并在主机上限制来源 IP |
| 上游安装脚本或程序包被篡改 | 安装后的面板版本或文件校验不符 | 脚本按 tag 存快照并随契约评审 diff，不在目标机 `curl \| bash`；程序包由脚本校验 SHA-256（Ruling-69） |
| 参考项目的实现缺陷被一并照搬 | 评审时发现与 Malio 源码逐行对应的逻辑 | 只借规则不搬代码（Ruling-17）；金额与余额变更一律事务内完成并写流水 |
| 自助注册被滥用（批量注册、刷签到） | 注册量或签到量异常 | 默认仅邀请注册；注册、发码、签到接口按 IP 与账号限流 |
| 契约反复变更 | M0 后仍频繁改 `hub-api.yaml` 的已有接口 | 非阻塞缺口记进《任务与边界》，按 tag 批量清账 |
