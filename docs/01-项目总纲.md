# 01 · 项目总纲

## 1. 定位

多服务器 3x-ui 节点聚合与订阅分发平台：把多台服务器上各自独立的 3x-ui 面板（不同协议的入站）聚合起来，
按权限派发给不同用户，对外只给每个用户一个订阅地址，并支持用户自行配置链式代理。
来源：已获批规划（2026-11-11）；2026-11-13 扩充自助运营与界面方向（Ruling-17 – Ruling-22）。

## 2. 范围

**范围内**

- 接入多台 3x-ui（v3.x）面板；在平台上增删改查各服务器的入站（节点）与 Host。
- 节点目录、节点组、套餐模板；用户的流量、到期、可用节点授权；自动下发到各面板并对账。
- 订阅：Base64 链接 / Mihomo YAML / sing-box JSON / Xray JSON，带 `Subscription-Userinfo` 头。
- 链式代理：客户端链式（订阅里渲染）先做；服务端链式（改入口面板 Xray 配置）后做。
- 四个端：管理门户、管理端（左侧菜单 RBAC）、客户门户、客户后台（左侧菜单按系统开关与用户状态显隐）。
- 自助运营（Ruling-18）：注册与邀请、商店、钱包、充值码、优惠码、扣余额自动续费、邀请返利、签到、公告、工单、
  教程与下载、邮件通知；功能与界面形式参考 SSPanel-Uim Malio（Ruling-17），界面规则见 05 / 06 篇。
- 运营工具：管理端收入与用户统计、切换为用户身份、节点掉线告警、Telegram 机器人、落地页、中英双语。

**范围外**（有人提就拒，或另立项）

- 转发代理流量（v2-hub 只做控制面，Ruling-4）。
- 3x-ui v2.x 及更早版本。
- 具体的在线支付网关（M5 只做网关抽象、余额与充值码，接哪家另行决定，Ruling-18）。
- 多级代理商 / 组织层级（客户模型为单层，Ruling-11）。
- 依赖自有节点后端的功能：限速、审计规则、SS/SSR 连接设置、流量倍率等（Ruling-22）。
- 本次只实现 3x-ui；S-UI 等其它面板经 Provider 抽象后续接入（Ruling-8）。

## 4. 验收 / 演示脚本

1. 管理员登录管理端，接入两台 3x-ui，看到两台服务器的入站自动出现在节点目录。
2. 在平台上给服务器 A 新建一个 VLESS+Reality 入站，面板 A 上随之出现。
3. 建套餐（含 A、B 的节点组），建用户并分配套餐；两台面板上自动出现该用户的 client。
4. 用户登录客户后台，复制 Mihomo 订阅导入客户端，所有节点可连通。
5. 用户配置链式代理“A 入口 → B 落地”，刷新订阅后该链路出口 IP 为 B。
6. 用户流量用尽后，两台面板上的 client 被自动禁用，订阅信息页显示已用尽。
7. 新用户凭邀请码注册，用充值码充值后在商店购买套餐；到期时余额足够则自动续费，不足则停止并收到邮件。

## 5. 成功标准

1. 任一成员 clone 全新目录，按 README 十分钟内起中间件 + 自己模块。
2. 上面 6 幕在两台真实 3x-ui 上全部跑通，并固化为 IT 用例。
3. service 层代码中搜索不到 3x-ui 专有路径（`/panel/api`）。
