# 03 · 业务语义（唯一权威；改动先改本篇再改代码）

> 脚手架阶段只钉死术语与框架；状态机、权限码、错误码随各里程碑补全，补一条登记一条。

## 1. 领域模型与术语

| 术语 | 定义 | 出现在 |
|---|---|---|
| 管理员 admin | 登录管理端的人；权限来自所属角色 | `admin`、`admin_role` |
| 角色 role / 权限码 permission | RBAC；权限码与管理端菜单、接口一一对应 | `role`、`permission`、`role_permission` |
| 用户 user | 终端用户（单层模型，Ruling-11），由管理员创建或自助注册（M4，Ruling-18），登录客户后台 | `end_user`（M2，避开保留字 user） |
| 服务器 server | 一台装了 3x-ui 的机器在平台上的登记；`provider_type` 区分面板实现 | `server`（M1） |
| 入站 inbound | 面板上的一个监听配置（协议 + 端口 + 传输 + 安全）；面板是事实来源 | `inbound`（M1） |
| Host / 端点 endpoint | 入站对外地址的覆盖（如 CDN 域名）；一个入站可有多个 | 3x-ui hosts |
| 节点 node | 面向用户的可选线路 = 服务器 × 入站 × 端点；有显示名、地区、标签、排序 | `node`（M1） |
| 节点组 node group | 节点集合，套餐按组授权 | `node_group`（M1） |
| 套餐 plan | 流量、时长、节点组、功能开关（链式、自有落地）的模板 | `plan`、`plan_node_group`（M2） |
| 下发 provision | 用户在某面板上对应的 client 及对账状态 | `provision`、`user_traffic_hourly`（M2） |
| 订阅 subscription | `/sub/{token}`，按格式渲染用户全部可用节点 | `end_user.sub_token_*`、`subscribe_log`（M3） |
| 分享链接 share link | 面板为某个 client 生成的节点地址（`vless://` 等），订阅的节点参数来源 | `provision.links_enc`（M3） |
| 系统设置 setting | 管理端可改的运营开关与参数，键固定、值有类型；凭据不进这张表 | `setting`（M4） |
| 邀请码 invite code | 注册时填写的码；用户各有一个个人码，管理员可另发 | `invite_code`（M4） |
| 邮箱验证码 email code | 发到邮箱的 6 位数字，用于注册、找回口令、换绑邮箱 | `email_code`（M4） |
| 公告 / 教程 / 共享账号 | 管理员维护、用户只读的内容 | `announcement`、`tutorial`、`shared_account`（M4） |
| 工单 ticket | 用户与管理员之间的一问一答对话 | `ticket`、`ticket_message`（M4） |
| 客户端链式 | 只在订阅里表达的入口 → 落地链路 | `chain_rule.kind=client`（M6） |
| 服务端链式 | 改入口面板 Xray 出站与路由实现的链路 | `chain_rule.kind=server`（M7） |
| 漂移 drift | 面板侧被直接修改，导致与平台缓存不一致 | 同步任务（M1） |

## 2. 状态机

**服务器连接状态** `server.status`：`unknown`（刚接入未探测）/ `online` / `offline`（网络不通、超时、5xx）/ `auth_failed`（面板返回 401/403，token 失效或被删）。

**用户状态** `user.status`（由平台判定，优先级从高到低）：`disabled`（管理员停用）> `expired`（到期且没有可用的自动续期）> `limited`（已用 ≥ 流量额度）> `active`。
非 `active` 的用户在各面板上的 client 一律禁用。

**下发状态** `provision.status`：`pending`（期望已变、尚未写到面板）/ `synced`（面板与期望一致）/ `failed`（写面板失败，按退避重试）。

## 3. 转移表（T-N，代码里的表驱动实现与本表逐行对应）

| T | From | 触发 | 守卫 | To | 副作用 |
|---|---|---|---|---|---|
| T1 | 任意 | 探测成功 | — | `online` | 记录面板版本、面板 GUID、资源快照、`last_seen_at`；清空 `last_error` |
| T2 | 任意 | 探测失败：网络 / 超时 / 5xx / 响应无法解析 | — | `offline` | 记录脱敏后的 `last_error`；不清空已缓存入站 |
| T3 | 任意 | 探测失败：面板返回 401/403 | — | `auth_failed` | 同 T2；需管理员更新 token |
| T4 | 任意 | 管理员禁用服务器 | — | 状态不变 | 停止探测与同步；节点不再参与派发（M2） |

用户（U-N，M2；配额模型照 3x-ui 的 client：额度、到期、首次使用后生效、自动续期、周期重置）：

| U | From | 触发 | 守卫 | To | 副作用 |
|---|---|---|---|---|---|
| U1 | — | 管理员创建用户（可同时分配套餐） | — | 按额度 / 到期判定 | 写期望状态，触发对账 |
| U2 | `active` | 流量任务累加后已用 ≥ 额度 | 额度 > 0 | `limited` | 期望改为禁用，触发对账 |
| U3 | `active` / `limited` | 到达到期时间 | 到期 > 0 | `expired` | 有自动续期且未达次数上限时改走 U4 |
| U4 | `expired` | 自动续期（每 N 天 / 每月几号 / 每周几） | 续期次数 < 上限（0 不限） | 按额度判定 | 到期按规则顺延到晚于当前时刻，已用清零，续期次数 +1 |
| U5 | `limited` / `active` | 周期流量重置（每小时 / 天 / 周 / 月，月度可指定几号） | 未到期 | `active` | 已用清零，到期不变 |
| U6 | 任意（`disabled` 除外） | 管理员分配或续费套餐 | — | `active` | 套餐数值拷到用户；未到期从原到期日顺延，已到期从当前时刻起算；已用清零 |
| U7 | 任意（`disabled` 除外） | 管理员直接改已用 / 额度 / 到期 | — | 重新判定 | 记审计 |
| U8 | 任意 | 管理员停用 / 启用 | — | `disabled` / 重新判定 | 期望随之改变，触发对账 |
| U9 | — | “首次使用后生效”的用户第一次产生流量 | 到期 < 0 | 状态不变 | 到期改为当前时刻 + 时长 |

## 4. 权限码表

命名 `<资源>:<动作>`，动作只有 `read` / `write`；`write` 不隐含 `read`，角色需同时授予。
内置角色 `super_admin` **隐式拥有全部权限码**（代码判定，不依赖 `role_permission` 行），新增权限码无需回填。
权限码清单以本表为准，`init.sql` 的种子数据与代码常量逐行对应。

| 权限码 | 对应菜单 / 接口 | 里程碑 |
|---|---|---|
| `admin:read` / `admin:write` | 系统 → 管理员与角色 | M0 |
| `audit:read` | 系统 → 审计日志 | M0 |
| `server:read` / `server:write` | 服务器管理 | M1 |
| `node:read` / `node:write` | 节点管理（含入站与 Host 增删改查） | M1 |
| `user:read` / `user:write` | 用户管理（含用量调整、下发状态与重试） | M2 |
| `plan:read` / `plan:write` | 套餐管理 | M2 |
| `setting:read` / `setting:write` | 系统 → 系统设置（含发测试邮件） | M4 |
| `content:read` / `content:write` | 公告、教程与下载、共享账号 | M4 |
| `ticket:read` / `ticket:write` | 工单（查看 / 回复与关闭） | M4 |

邀请码的管理归 `user:read` / `user:write`。

### 4.1 授权规则（防垂直越权，R-N）

| R | 规则 |
|---|---|
| R1 | 管理接口按权限码鉴权；未登录 401 `unauthenticated`，缺权限码 403 `permission_denied`。 |
| R2 | 只能授予自己拥有的权限码：创建 / 修改角色时，权限集合必须是操作者权限的子集。 |
| R3 | 只能分配权限集合是自己子集的角色；`super_admin` 角色只能由 `super_admin` 分配或收回。 |
| R4 | 不能经管理员管理接口修改自己（角色、禁用状态），返回 409 `conflict`；改自己的口令允许。 |
| R5 | 系统中至少保留一个启用状态的 `super_admin`；会导致违反的禁用 / 改角色操作返回 409 `conflict`。 |
| R6 | 内置角色（`is_builtin`）不可删除、不可改权限；被管理员引用的角色不可删除（409）。 |
| R7 | 管理员被禁用或改密码时，其全部会话立即失效。 |

## 4.2 管理员会话与登录

| 项 | 约定 |
|---|---|
| 会话载体 | 服务端会话表 `admin_session`；Cookie `hub_admin_session` 只存随机 token（≥ 256 bit），库里只存其 SHA-256 |
| Cookie 属性 | HttpOnly、SameSite=Lax、Path=`/api/admin`；生产 Secure（配置 `auth.secureCookie`） |
| 有效期 | 空闲 2 小时过期（每次请求顺延，写库节流 1 分钟）；绝对 7 天过期；登出即删除 |
| CSRF | 每个会话一个随机 CSRF token；登录与 `GET /api/admin/auth/me` 返回；非 GET/HEAD 请求必须带 `X-CSRF-Token`，不符返回 403 `permission_denied` |
| 登录频控 | 同一用户名或同一 IP 15 分钟内失败 5 次即锁定 15 分钟，返回 429 `rate_limited`；锁定期间正确口令也拒绝 |
| 失败提示 | 用户名不存在、口令错误、账号禁用统一返回 401 `unauthenticated`“用户名或密码错误”，不暴露哪一项错 |
| 口令 | argon2id（m=19 MiB, t=2, p=1，OWASP 基线）；长度 12–128 字符 |
| 审计 | 登录成功 / 失败、登出、管理员与角色的增删改都写 `audit_log`，不记录口令与 token |

## 4.3 两步验证

管理员可自愿开启 TOTP 两步验证（RFC 6238：HMAC-SHA1、30 秒、6 位，兼容常见验证器 App）。

| 项 | 约定 |
|---|---|
| 开启 | ① `setup` 生成 160 bit 随机密钥，加密存入 `admin.totp_pending_enc`，返回 `otpauth://` 地址与 Base32 密钥（仅此一次）；② `enable` 提交当前验证码，校验通过后转存 `totp_secret_enc` 并清空待定密钥。重复 `setup` 覆盖待定密钥 |
| 登录 | 已开启的账号，口令正确但未带 `totpCode` 返回 401 `totp_required`（前端据此显示验证码输入框）；验证码错误按登录失败计入频控，提示统一为“验证码错误” |
| 时间窗 | 允许前后各 1 个 30 秒步长的时钟偏差 |
| 防重放 | 每个账号记录最近一次成功使用的步长 `totp_last_step`，同一或更早步长的验证码不再接受 |
| 关闭 | 本人提交当前验证码后关闭；遗失设备时由有 `admin:write` 的管理员按 R3 清除（不能对自己操作，R4），被清除者全部会话失效（R7 同理） |
| 存储 | 密钥用 AES-256-GCM 加密，主密钥来自环境变量 `HUB_ENCRYPTION_KEY`（Base64 的 32 字节），不入库、不入配置文件 |
| 审计 | `admin.totp_enable`、`admin.totp_disable`、`admin.totp_reset` |

## 5. 错误码表

信封 `{code, message, data}`，`code = "0"` 为成功。

| code | HTTP | 含义 |
|---|---|---|
| `0` | 200 | 成功 |
| `invalid_argument` | 400 | 参数校验失败 |
| `unauthenticated` | 401 | 未登录或会话过期 |
| `permission_denied` | 403 | 无权限码或越权访问他人数据 |
| `not_found` | 404 | 资源不存在 |
| `conflict` | 409 | 唯一性冲突或版本冲突 |
| `rate_limited` | 429 | 触发频控 |
| `totp_required` | 401 | 口令正确，但该账号已开启两步验证，需要再提交验证码 |
| `upstream_unavailable` | 502 | 面板不可达、拒绝 token 或返回异常（message 给出脱敏后的原因）；面板收到请求但拒绝执行（如端口冲突）按 400 `invalid_argument` 返回面板给出的原因 |
| `account_disabled` | 403 | 用户账号已被停用；客户后台只允许查看本人信息与退出 |
| `feature_disabled` | 403 | 该功能未开启（注册关闭、签到 / 工单未开、邮件未配置等），message 说明是哪一项 |
| `internal` | 500 | 未分类内部错误（日志带上下文） |

## 5.1 服务器、入站与节点（M1）

| 项 | 约定 |
|---|---|
| 面板类型 | `server.provider_type`，当前只有 `xui`（3x-ui ≥ v3.0，Ruling-7、Ruling-8） |
| 接入信息 | 面板根地址（含 scheme、端口、web base path）+ API token（3x-ui 用 `admin` 范围）；token 以 `server:<id>:token` 为关联数据 AES-256-GCM 加密存储，只写不读 |
| TLS 校验 | `verify`（默认，系统 CA）/ `pin`（只认指定叶子证书 SHA-256，适合自签证书）/ `skip`（不校验，仅调试，界面明示风险）；`http://` 仅允许用于内网或本机调试 |
| 探测与同步 | 健康探测默认每 30 秒一次（T1–T3），入站同步默认每 5 分钟一次，另可手动“立即同步”；并发按服务器数限流 |
| 入站来源 | 面板是入站配置的事实来源（02 篇铁律二）。平台写入面板成功后立即回读并落库；缓存副本删除敏感字段（Reality 私钥、证书私钥内容、服务端口令），编辑时由 Provider 从面板原值补回 |
| 客户端字段 | 入站的 `clients` 列表不归入站管理（M2 由下发对账维护）；编辑入站时始终保留面板上的现有 clients |
| 漂移 | 每次平台写入后记录配置摘要 `synced_hash`（不含 clients 与流量计数）；同步时面板摘要与之不同即记 `drift_detected_at`，以面板为准覆盖缓存，管理员确认后清除标记。面板上已删除的入站标记 `is_missing`，不自动删除平台记录 |
| 缺失入站 | `is_missing` 是终态：同一面板标识再次出现时一律视为新入站、新建平台记录，旧记录不复活。缺失入站只能删除（只删平台记录，不再调用面板），编辑、启停、确认漂移、添加对外地址返回 409 |
| 面板标识复用 | 面板会把已删入站的标识分给新入站（3x-ui 的数字 id）。平台新建入站时，若该标识仍挂在一条未缺失的平台记录上，说明那条记录对应的入站已被删，先将其标记缺失再新建；同步时同一标识的协议变了，同样按“旧的缺失 + 新的新增”处理。旧记录的节点与节点组成员关系留在旧记录上，不转给新入站 |
| 删除入站 | 先删面板、再删平台记录及其节点；面板返回成功或“已不存在”都视为删除成功 |
| 删除对外地址 | 只删所点的那一个（入站 × 地址）。3x-ui 的 Host 组是“入站集合 × 地址集合”，删除时由 Provider 改写所在组：组里只剩这一对就删组；只涉及一个入站或一个地址就缩小组；否则拆成两组，被移到新组的地址保留原平台记录与节点。面板上已不存在的地址只删平台记录 |
| 节点 | 每个入站自动生成一个“直连”节点；入站上每个 Host 地址再各生成一个节点。节点有显示名、地区、标签、排序、启停，均只影响平台展示与派发，不写回面板 |
| 节点组 | 节点的命名集合，一个节点可属多个组；套餐按组授权（M2） |
| 入站表单 | 与 3x-ui 同构（Ruling-16）：基础（启用、备注、协议、监听地址、端口）/ 协议 / 传输 / 安全（无、TLS、Reality）/ 嗅探 / 高级 JSON。协议覆盖 Xray 内核的 vless、vmess、trojan、shadowsocks、hysteria、wireguard、http、mixed、tunnel；提交时以 protocol + config（settings / streamSettings / sniffing）写入面板。服务端模板（`vless-reality`、`vmess-ws`、`shadowsocks-2022`）保留给接口调用 |
| 入站密钥 | 照 3x-ui（Ruling-16）：表单显示私钥与口令。Reality x25519、ML-DSA-65、VLESS encryption 由面板生成（平台代理面板的生成接口）；UUID、Short ID、SS2022 密钥、WireGuard 密钥在浏览器用安全随机数生成。编辑时从面板实时读取完整配置（含密钥，不含 clients），每次读取记审计；平台缓存仍删除敏感字段（Ruling-14） |

## 5.2 用户、套餐与下发（M2）

| 项 | 约定 |
|---|---|
| 用户 | 用户名（登录客户后台用，3–64 位）、口令（argon2id，管理员设初始口令）、备注、所属套餐，以及从套餐拷来的额度、到期、IP 限制、自动续期、周期重置；一个用户只有一个套餐 |
| 套餐 | 名称、流量额度（字节，0 不限）、时长（天，0 不限；可选“首次使用后开始计时”）、节点组（多选）、同时在线 IP 数（0 不限）、自动续期（每 N 天 / 每月几号 / 每周几三选一，最多次数 0 不限）、周期流量重置（不重置 / 每小时 / 天 / 周 / 月，月度几号）、功能开关（客户端链式、自有落地，M6 起生效） |
| 分配与续费 | 见 U6。套餐改了不影响已分配的用户，直到管理员对该用户再次分配或续费 |
| 用量 | 已用 = 各面板上行 + 下行之和，不设倍率。流量任务默认每分钟拉一次各面板 client 流量，按上次读数求增量累加；面板读数变小视为面板侧清零，增量取当前读数。按小时留用量明细（客户后台流量明细用，M3） |
| 管理员改用量 | 可直接清零已用、设置已用值、改额度、改到期、改 IP 限制（U7），每次记审计 |
| 授权 | 用户可用节点 = 套餐节点组里的节点，且节点启用、来源入站未缺失、所在服务器未停用；按入站去重得到期望的（用户, 入站）集合 |
| 下发 | 每个用户在每台面板上一个 client（email 见 §6），凭据（UUID、口令、SS2022 用户密钥等）由平台生成并在各面板一致；client 挂到该面板上所有被授权的入站。面板上的 client 不设额度与到期，配额与到期只由平台判定；用户非 `active` 时 client 禁用 |
| 对账 | 期望状态变更即触发，另每 5 分钟兜底一次。只管 email 符合平台规则的 client，面板上其它 client 不碰。按差异新建 / 挂载 / 卸载 / 启停 / 删除；同一面板的操作合并成批（禁用 client 会触发 Xray 重启）。结果写 `provision`，失败按指数退避重试，管理员可手动重试 |
| 删除用户 | 先删各面板上的 client，再删平台记录；面板不可达时记为待删除，恢复后由对账完成。没有任何面板 client 的用户当场删除平台记录；未关闭的工单在删除时一并删除，不等对账 |

## 5.3 终端用户会话与账号（M3）

规则与管理员侧（§4.2、§4.3）同构，实现复用；差异如下表。

| 项 | 约定 |
|---|---|
| 会话 | 会话表 `user_session`；Cookie `hub_user_session`，HttpOnly、SameSite=Lax、Path=`/api/user`，生产 Secure；库里只存 token 的 SHA-256 |
| 有效期 | 空闲 7 天过期（请求顺延，写库节流 1 分钟），绝对 30 天过期；登出即删除 |
| CSRF | 与 §4.2 相同：登录与 `GET /api/user/auth/me` 返回 token，非 GET/HEAD 请求必须带 `X-CSRF-Token` |
| 登录 | 用用户名或邮箱登录（M4）：先按用户名找，找不到且输入含 `@` 时按邮箱找；频控与失败提示同 §4.2（同一用户名或同一 IP 15 分钟 5 次失败锁 15 分钟，提示不区分哪一项错） |
| 口令 | argon2id；长度 8–128 字符。本人改口令须提交旧口令，成功后其余会话全部失效；管理员重置口令后该用户全部会话失效 |
| 两步验证 | 自愿开启，规则同 §4.3；关闭须提交当前验证码；遗失设备由有 `user:write` 的管理员清除，被清除者全部会话失效 |
| 归属（R8） | 用户接口的身份只取自会话，不接受请求中的用户 id；只能读写本人数据，访问他人资源一律 404 |
| 停用 | `disabled` 的用户可以登录，但除 `auth/me` 与登出外的接口返回 403 `account_disabled`；订阅只返回一条说明状态的信息节点 |
| 登录记录 | 每次登录成功 / 失败记 `user_login_log`（时间、IP、结果），本人可见最近 10 条，保留 90 天；不记口令与验证码 |
| 审计 | 管理员对用户的操作照旧写 `audit_log`；用户本人的操作（改口令、两步验证、重置订阅）写 `user_login_log` 之外的 `audit_log`，操作者记为该用户 |

## 5.4 订阅（M3）

| 项 | 约定 |
|---|---|
| 地址 | `GET /sub/{token}`，无需登录；每个用户一个 token，首次进入客户后台或创建用户时生成。库里存两份：`sub_token_hash`（SHA-256，用于查找）与 `sub_token_enc`（AES-256-GCM，关联数据 `end_user:<id>:sub`，用于在客户后台再次显示） |
| 重置 | 用户本人或有 `user:write` 的管理员可重置：换新 token，**同时轮换连接凭据**（UUID 与口令），旧地址与旧凭据立即失效并触发对账；客户端需重新导入。面板不可达时该面板的旧凭据在恢复后由对账换掉 |
| 格式 | `?format=` 取 `base64`（分享链接列表）/ `mihomo` / `singbox` / `xray`；未指定时按 User-Agent 判断：含 clash、mihomo、stash 用 `mihomo`，含 sing-box、SFA、SFI、SFM 用 `singbox`，其余用 `base64`。不认识的取值返回 400 |
| 节点来源 | 订阅不回源面板（02 篇铁律四）。对账时向面板取该 client 的分享链接，加密存入 `provision.links_enc`（关联数据 `provision:<id>:links`）；只在新建、换凭据、挂载变化、尚无链接，或该面板的入站 / 对外地址摘要变化时重取，取失败记该用户本轮下发失败并重试。面板生成的链接是节点参数的唯一来源，平台不自行拼装协议参数 |
| 节点与链接对应 | 同一服务器内：链接的（地址，端口）等于某个对外地址节点的，就对应该节点；其余链接，端口等于入站端口且地址不是该入站任何对外地址的，对应该入站的直连节点。直连节点对外用平台登记的服务器地址（面板给出的是它自己认定的主机名，不可靠）。面板只为有对外地址的入站输出对外地址链接，这类入站的直连节点没有链接、不输出。对应不上、节点或入站停用、不在用户授权范围内的链接不输出。输出名称用节点显示名，顺序按节点排序值、再按名称 |
| 统一模型 | 链接先解析为 `ProxyNode`（协议、地址、端口、凭据、传输、安全参数），再渲染各格式；解析不了的链接跳过并记日志（不含凭据）。覆盖 vless、vmess、trojan、shadowsocks、hysteria2 |
| 完整配置 | `mihomo` 与 `singbox` 输出可直接运行的完整配置：一个手动选择组、一个自动测速组；规则只有三类——私有网段直连、中国大陆地址直连、其余走代理。`xray` 输出一个数组，每个节点一份完整的 Xray 客户端配置（`remarks` 为节点名，形状与 3x-ui 的 JSON 订阅一致），说明节点与 hysteria2 不输出；`base64` 只有链接 |
| 用量信息 | 响应头 `Subscription-Userinfo: upload=0; download=<已用>; total=<额度>; expire=<到期秒数>`（不限则省略对应项）、`Profile-Update-Interval`、`Profile-Title`、`Content-Disposition` |
| 信息节点 | 可配置（默认开）：在节点前附两条不可连通的说明节点“剩余流量”“到期时间”。用户非 `active` 时不输出真实节点，只输出一条说明原因的信息节点 |
| 记录 | 每次成功拉取记 `subscribe_log`（时间、格式、IP、User-Agent 截断到 255 字符），默认保留 30 天；本人可见自己的，管理员凭 `user:read` 可查全部 |
| 频控 | 同一 token 每分钟 30 次、同一 IP 每分钟 60 次，超出返回 429；token 不存在返回 404，并按 IP 计入失败频控（15 分钟 20 次即锁 15 分钟），防枚举 |
| 设置 | 对外基地址、更新间隔（小时）、标题、信息节点开关、记录保留天数：M3 放配置文件 `subscription` 段，M4 起移入系统设置表由管理端修改 |
| 凭据处理 | 订阅地址与分享链接视同凭据：不进日志、不进审计详情；客户后台默认打码，点击才显示 / 复制 |

## 5.7 邮件（M4）

| 项 | 约定 |
|---|---|
| 配置 | SMTP 主机、端口、账号、口令、发件人、加密方式（`starttls` / `tls` / `none`）全部走环境变量（`HUB_SMTP_*`，Ruling-24）。主机或发件人为空即“邮件不可用”：注册验证码、找回口令、换绑邮箱、公告群发、工单通知整体关闭，相关接口返回 403 `feature_disabled` |
| 发件箱 | 所有邮件先写 `mail_outbox` 再由后台任务发送，接口不等 SMTP。失败按指数退避重试，最多 5 次；正文加密存储（AES-256-GCM，关联数据 `mail_outbox:<随机键>`），发送成功或放弃后清空正文，只留收件人、主题、状态；记录保留 30 天 |
| 速率 | 全局按 `mail.ratePerMinute` 限速，验证码类邮件优先于群发 |
| 内容 | 模板内置在后端（纯文本 + 简单 HTML 两份），变量只做转义后的文本替换；不接受用户提供的 HTML |
| 测试 | `setting:write` 可向指定地址发一封测试邮件，直接返回 SMTP 结果（脱敏） |
| 日志 | 日志与审计不记邮件正文与验证码；收件人在日志里打码（`a***@example.com`） |

**邮箱验证码**（Ruling-23：注册、找回口令、换绑都用验证码，不发链接）

| 项 | 约定 |
|---|---|
| 形式 | 6 位数字，10 分钟有效；库里只存 HMAC-SHA256（密钥由主密钥派生），不存明文 |
| 用途 | `register` / `reset` / `bind`，互不通用；同一邮箱同一用途只有最新一条有效 |
| 校验 | 一条验证码最多校验 5 次，超出即作废；校验通过即作废（一次性） |
| 发码频控 | 同一邮箱每分钟 1 次、每小时 5 次；同一 IP 每小时 20 次；超出 429 |
| 不泄露存在性 | 找回口令的发码接口对不存在的邮箱同样返回成功，只是不发信 |

## 5.8 注册、邀请与账号自助（M4）

| 项 | 约定 |
|---|---|
| 注册方式 | `open`：任何人可注册，邀请码可选；`invite`：必须有有效邀请码；`closed`：返回 403 `feature_disabled`。管理员手动建号不受影响 |
| 注册字段 | 用户名（3–64 位字母、数字、`_`、`.`、`-`；自 M4 起新建用户名不再允许 `@`，存量保留）、邮箱（必填，≤ 254 字符，存小写，全站唯一）、口令（8–128）、邀请码（视方式）、邮箱验证码（`register.emailVerify` 生效时必填） |
| 邮箱域名 | 先过黑名单再过白名单，不通过返回 400，提示“该邮箱域名不支持注册” |
| 冲突 | 用户名或邮箱已被占用返回 409（注册表单无法避免暴露占用情况，靠频控约束）。邮箱不得与任何现有用户名相同（存量用户名可能含 `@`），注册与换绑时一并判重 |
| 频控 | 同一 IP 每小时成功注册 3 个、每小时提交 20 次；超出 429 |
| 注册结果 | 建用户（邮箱视为已验证，若未要求验证码则记为未验证）→ 记录邀请关系 → 若 `register.planId` 非 0 则分配该套餐并触发对账 → 直接登录（下发会话 Cookie） |
| 邀请码 | 10 位随机字母数字（去掉易混字符），不区分大小写。两类：个人码（每个用户一个，首次查看时生成，可重置，重置后旧码作废；次数上限取 `invite.userMaxUses`）与管理员码（自定可用次数、到期时间、备注，可停用）。使用一次计数加一，计数与上限的判断在同一事务内完成（并发注册不超发） |
| 邀请关系 | `end_user.invited_by`（邀请人，可空）与 `invite_code_id`；邀请人被删除后置空。本人可见“我邀请的人”列表（只显示打码用户名与注册时间）。返利在 M5 |
| 邮箱绑定 | 管理员建的用户可以没有邮箱。本人绑定 / 换绑：提交当前口令 + 发到新邮箱的 `bind` 验证码；管理员可直接改用户邮箱（视为已验证）。邮件不可用时本人不能自助换绑 |
| 找回口令 | ① 提交邮箱 → 发 `reset` 验证码（不存在的邮箱也返回成功）；② 提交邮箱 + 验证码 + 新口令 → 改口令并让该用户全部会话失效。**不关闭两步验证**，登录仍须验证码。没有邮箱或邮件不可用时只能找管理员重置 |
| 注销账号 | 本人提交当前口令（已开两步验证的另须验证码）后注销：按“删除用户”处理（§5.2），用户名与邮箱随即可被重新注册；未关闭的工单一并删除 |
| 审计 | 注册、找回口令、换绑邮箱、注销、邀请码的生成 / 重置 / 停用都写 `audit_log`，不记口令与验证码 |

## 5.9 公告、教程与共享账号（M4）

三者都是“管理员维护、用户只读”，权限码 `content:*`。

| 项 | 约定 |
|---|---|
| 正文格式 | Markdown 源文本（≤ 20000 字符）。前端渲染时不执行原始 HTML，链接只允许 `http` / `https` / `mailto`（Ruling-25） |
| 公告 | 标题（1–100）、正文、置顶、弹窗、发布时间（空 = 草稿）。用户只见已发布的，置顶在前、新的在前；仪表盘显示最新一条，标了“弹窗”的最新一条在进入仪表盘时弹出，用户关闭后同一条不再弹（记在浏览器本地） |
| 公告群发 | 发布时可勾选“同时邮件通知”：给所有有已验证邮箱且未停用的用户各入一封发件箱邮件；每条公告只能群发一次。邮件不可用时不可勾选 |
| 教程与下载 | 按平台（`windows` / `macos` / `android` / `ios` / `linux` / `router`）分组的条目：客户端名、简介、下载链接（≤ 5 个，各含名称与 `https` 地址）、正文、排序、是否发布。用户页按平台分卡，每篇教程内嵌该用户的一键导入按钮（地址来自 §5.4，不写进教程正文） |
| 共享账号 | 名称、分类（1–32）、账号、口令、备注、排序、是否发布；可限定套餐（不选 = 所有有套餐的用户可见）。口令加密存储（AES-256-GCM，关联数据 `shared_account:<id>`）。只有 `active` 且符合套餐限定的用户能看到条目；列表不带口令，点“显示”才单独取，取一次记一条审计（不记口令）。`shared.enabled` 关闭时用户侧接口返回 403 `feature_disabled` |

## 5.10 工单（M4）

| 项 | 约定 |
|---|---|
| 状态 | `open`（等管理员回复）/ `answered`（等用户回复）/ `closed`。用户新建或回复 → `open`；管理员回复 → `answered`；双方都可关闭；用户回复已关闭的工单即重新打开 |
| 内容 | 主题 1–100 字符；每条消息 1–5000 字符的纯文本，按原样显示（保留换行，不解析 Markdown 与 HTML）；M4 不支持附件 |
| 归属 | 用户只能看到与操作自己的工单，他人的一律 404（R8）；消息记录作者类型（用户 / 管理员）与作者，用户侧只显示“客服”，不显示管理员用户名 |
| 限制 | 每个用户未关闭的工单最多 5 张；每小时新建 5 张、回复 30 条，超出 429 |
| 管理端 | `ticket:read` 看列表（按状态筛选、按最近回复排序）与对话，`ticket:write` 回复与关闭 |
| 通知 | 管理员回复后给用户的已验证邮箱发一封提醒（不含回复正文，只说“工单有新回复”）；用户新建 / 回复时若设了 `ticket.notifyEmail` 则通知该邮箱。邮件不可用时不通知 |
| 停用用户 | 按 §5.3，`disabled` 的用户不能使用工单 |

## 5.11 签到（M4）

| 项 | 约定 |
|---|---|
| 条件 | `checkin.enabled` 为真；用户有套餐、流量额度不是“不限”、状态为 `active` 或 `limited`。不满足返回 409 并说明原因 |
| 频率 | 每个用户每个自然日（`site.timezone`）一次；由 `(user_id, 日期)` 唯一约束保证，并发提交只有一次成功，其余返回 409“今天已经签到” |
| 奖励 | 在 `[checkin.minMb, checkin.maxMb]` 内均匀随机取整数 MB，加到当前流量额度上；与写签到记录在同一事务内完成。`limited` 的用户因此回到额度以内时状态重算为 `active` 并触发对账 |
| 与续费的关系 | 奖励加在当前额度上；续费、重新分配套餐或管理员改额度时额度被整体覆盖，此前的签到奖励不保留。周期流量重置只清已用，不动额度 |
| 记录 | `checkin_log`（日期、奖励字节数），本人可见最近 30 条 |

## 6. 编号与约定

- 面板上的 client email 由平台生成：`u{userId}-{6 位随机短码}`，同一用户在各面板一致；不得含用户真实邮箱或手机号。
- 平台在面板 Xray 配置里只增删 `hub-` 前缀的出站与路由规则（服务端链式，M7）。
- 邀请码：10 位，字符集去掉 `0O1IL`，存大写；邮箱一律存小写并按小写判重。
- 订阅 token：≥ 128 bit 随机，URL 安全 Base64；可重置，重置后旧 token 立即失效（§5.4）。
