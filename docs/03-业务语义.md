# 03 · 业务语义（唯一权威；改动先改本篇再改代码）

> 脚手架阶段只钉死术语与框架；状态机、权限码、错误码随各里程碑补全，补一条登记一条。

## 1. 领域模型与术语

| 术语 | 定义 | 出现在 |
|---|---|---|
| 管理员 admin | 登录管理端的人；权限来自所属角色 | `admin`、`admin_role` |
| 角色 role / 权限码 permission | RBAC；权限码与管理端菜单、接口一一对应 | `role`、`permission`、`role_permission` |
| 用户 user | 终端用户（单层模型，Ruling-11），由管理员创建或自助注册（M4，Ruling-18），登录客户后台 | `end_user`（M2，避开保留字 user） |
| 服务器 server | 一台装了 3x-ui 的机器在平台上的登记；`provider_type` 区分面板实现 | `server`（M1） |
| 入站 inbound | 面板上的一个监听配置（协议 + 端口 + 传输 + 安全）；面板是事实来源 | `inbound`（M1） |
| Host / 端点 endpoint | 入站对外地址的覆盖（如 CDN 域名）；一个入站可有多个 | 3x-ui hosts |
| 节点 node | 面向用户的可选线路 = 服务器 × 入站 × 端点；有显示名、地区、标签、排序 | `node`（M1） |
| 节点组 node group | 节点集合，套餐按组授权 | `node_group`（M1） |
| 套餐 plan | 流量、时长、节点组、功能开关（链式、自有落地）的模板 | `plan`、`plan_node_group`（M2） |
| 下发 provision | 用户在某面板上对应的 client 及对账状态 | `provision`、`user_traffic_hourly`（M2） |
| 订阅 subscription | `/sub/{token}`，按格式渲染用户全部可用节点 | `end_user.sub_token_*`、`subscribe_log`（M3） |
| 分享链接 share link | 面板为某个 client 生成的节点地址（`vless://` 等），订阅的节点参数来源 | `provision.links_enc`（M3） |
| 系统设置 setting | 管理端可改的运营开关与参数，键固定、值有类型；凭据不进这张表 | `setting`（M4） |
| 邀请码 invite code | 注册时填写的码；用户各有一个个人码，管理员可另发 | `invite_code`（M4） |
| 邮箱验证码 email code | 发到邮箱的 6 位数字，用于注册、找回口令、换绑邮箱 | `email_code`（M4） |
| 公告 / 教程 / 共享账号 | 管理员维护、用户只读的内容 | `announcement`、`tutorial`、`shared_account`（M4） |
| 工单 ticket | 用户与管理员之间的一问一答对话 | `ticket`、`ticket_message`（M4） |
| 时长选项 plan price | 套餐的一个可售规格：天数 + 价格；一个套餐可有多个 | `plan_price`（M5） |
| 流量包 traffic pack | 只加流量额度、不改到期的商品 | `traffic_pack`（M5） |
| 订单 order | 一次购买的记录，带下单时的商品快照与金额；只有“已支付”一种状态（Ruling-28） | `shop_order`（M5） |
| 余额 balance / 流水 ledger | 用户在平台内的预存金额（整数分）；每次变动一条流水 | `end_user.balance`、`wallet_ledger`（M5） |
| 充值码 topup code | 兑换后给余额加一笔固定金额的一次性码 | `topup_code`（M5） |
| 优惠码 coupon | 下单时填写、减免金额的码 | `coupon`、`coupon_usage`（M5） |
| 充值单 payment | 经支付网关给余额充值的一笔在线支付 | `payment`（M5） |
| 返利 rebate | 被邀请人消费后记给邀请人余额的金额 | `rebate`（M5） |
| 链式规则 chain route | 一组起飞节点 → 一个落地，有顺序（Ruling-46）；分客户端链式与服务端链式 | `chain_route`、`chain_route_entry`（M9，取代 M6 的 `chain_rule`） |
| 客户端链式 | 只在订阅里表达的两跳链路：落地经起飞节点拨出（Ruling-36） | `chain_route.kind=client` |
| 链式出口 chain exit | 只用作链路落地的外部节点（分享链接或 SOCKS5 地址）：管理员添加的平台出口，或用户自己添加的用户出口（M6 叫自有落地节点）（Ruling-47） | `chain_exit`、`node_group_exit`（M9，取代 M6 的 `custom_node`） |
| 服务端链式 | 起飞面板的 Xray 按用户把流量转给落地的链路，客户端无感（Ruling-39） | `chain_route.kind=server`、`chain_apply`（M7） |
| 漂移 drift | 面板侧被直接修改，导致与平台缓存不一致 | 同步任务（M1） |

## 2. 状态机

**服务器连接状态** `server.status`：`unknown`（刚接入未探测）/ `online` / `offline`（网络不通、超时、5xx）/ `auth_failed`（面板返回 401/403，token 失效或被删）。

**用户状态** `user.status`（由平台判定，优先级从高到低）：`disabled`（管理员停用）> `expired`（到期，且免费续期与扣余额续费都没有成功）> `limited`（已用 ≥ 流量额度）> `active`。
非 `active` 的用户在各面板上的 client 一律禁用。

**下发状态** `provision.status`：`pending`（期望已变、尚未写到面板）/ `synced`（面板与期望一致）/ `failed`（写面板失败，按退避重试）。

**链路下发状态** `chain_apply.status`（每台入口服务器一行，M7）：`pending`（面板上平台条目与期望不一致，待下发）/ `applied`（一致）/
`failed`（下发后 Xray 未能运行，已回滚；按退避重试，同一期望连续失败 3 次后停止自动重试）。

## 3. 转移表（T-N，代码里的表驱动实现与本表逐行对应）

| T | From | 触发 | 守卫 | To | 副作用 |
|---|---|---|---|---|---|
| T1 | 任意 | 探测成功 | — | `online` | 记录面板版本、面板 GUID、资源快照、`last_seen_at`；清空 `last_error` |
| T2 | 任意 | 探测失败：网络 / 超时 / 5xx / 响应无法解析 | — | `offline` | 记录脱敏后的 `last_error`；不清空已缓存入站 |
| T3 | 任意 | 探测失败：面板返回 401/403 | — | `auth_failed` | 同 T2；需管理员更新 token |
| T4 | 任意 | 管理员禁用服务器 | — | 状态不变 | 停止探测与同步；节点不再参与派发（M2） |

用户（U-N，M2；配额模型照 3x-ui 的 client：额度、到期、首次使用后生效、自动续期、周期重置）：

| U | From | 触发 | 守卫 | To | 副作用 |
|---|---|---|---|---|---|
| U1 | — | 管理员创建用户（可同时分配套餐） | — | 按额度 / 到期判定 | 写期望状态，触发对账 |
| U2 | `active` | 流量任务累加后已用 ≥ 额度 | 额度 > 0 | `limited` | 期望改为禁用，触发对账 |
| U3 | `active` / `limited` | 到达到期时间 | 到期 > 0 | `expired` | 先看 U4（管理员设的免费续期），不适用再看 U10（扣余额续费），都不成立才到期 |
| U4 | `expired` | 免费续期（每 N 天 / 每月几号 / 每周几；只能由管理员在用户上设置，Ruling-20） | 续期次数 < 上限（0 不限） | 按额度判定 | 到期按规则顺延到晚于当前时刻，已用清零，续期次数 +1 |
| U5 | `limited` / `active` | 周期流量重置（每小时 / 天 / 周 / 月，月度可指定几号） | 未到期 | `active` | 已用清零，到期不变 |
| U6 | 任意（`disabled` 除外） | 管理员分配或续费套餐 | — | `active` | 套餐数值拷到用户；未到期从原到期日顺延，已到期从当前时刻起算；已用清零 |
| U7 | 任意（`disabled` 除外） | 管理员直接改已用 / 额度 / 到期 | — | 重新判定 | 记审计 |
| U8 | 任意 | 管理员停用 / 启用 | — | `disabled` / 重新判定 | 期望随之改变，触发对账 |
| U9 | — | “首次使用后生效”的用户第一次产生流量 | 到期 < 0 | 状态不变 | 到期改为当前时刻 + 时长 |
| U10 | 到期时刻 | 扣余额自动续费（§5.16） | 开了自动续费；原时长选项仍在售；余额 ≥ 现价 | 按额度判定 | 扣余额、记流水与订单，按 U6 从原到期日顺延；任一守卫不成立则关闭自动续费、状态 `expired`、发通知 |
| U11 | 任意（`disabled` 除外） | 用户购买套餐的某个时长选项（§5.13） | 余额 ≥ 应付 | `active` | 同一套餐 = 续费（同 U6：未到期从原到期日顺延，已用清零，额度恢复为套餐值）；不同套餐 = 换购（立即生效，到期 = 现在 + 天数，原剩余时长不折算） |
| U12 | `active` / `limited` | 用户购买流量包（§5.13） | 有套餐且额度不是“不限”；余额 ≥ 应付 | 按额度判定 | 流量包字节数加到当前额度，到期不变 |

服务端链式下发（C-N，M7；每台起飞服务器独立，见 §5.19）：

| C | From | 触发 | 守卫 | To | 副作用 |
|---|---|---|---|---|---|
| C1 | 任意 | 下发任务发现面板上 `hub-` 条目与期望不同（规则增删改、套餐 / 节点 / 凭据变化、面板被人改动） | 服务器启用且在线；距上次下发 ≥ 60 秒；不处于 C4 的停止状态 | `pending` → 立即执行 C2 | — |
| C2 | `pending` | 写入新模板并重启 Xray，随后 Xray 处于运行状态 | — | `applied` | 写入前把整份模板加密备份；记录本次生效的规则 id；清零失败次数；写审计 |
| C3 | `pending` | 面板拒绝保存（3x-ui 保存前会校验配置），或重启后 Xray 未运行 | — | `failed` | 拒绝保存时模板未变，不回滚也不重启；重启后未运行则写回备份并再次重启。记录脱敏后的错误（面板或 Xray 给出的说明）；失败次数 +1，按 1 / 5 / 15 分钟退避；本次新增或有变、落地为用户出口的规则记为隔离（§5.19 失败隔离，M9） |
| C4 | `failed` | 同一期望失败次数达到 3 | — | `failed`（停止自动重试） | 等期望变化或管理员点“重试”（清零失败次数后回到 C1） |
| C5 | `applied` | 每轮检查一致 | — | `applied` | 无（不重启） |

## 4. 权限码表

命名 `<资源>:<动作>`，动作只有 `read` / `write`；`write` 不隐含 `read`，角色需同时授予。
内置角色 `super_admin` **隐式拥有全部权限码**（代码判定，不依赖 `role_permission` 行），新增权限码无需回填。
权限码清单以本表为准，`init.sql` 的种子数据与代码常量逐行对应。

| 权限码 | 对应菜单 / 接口 | 里程碑 |
|---|---|---|
| `admin:read` / `admin:write` | 系统 → 管理员与角色 | M0 |
| `audit:read` | 系统 → 审计日志 | M0 |
| `server:read` / `server:write` | 服务器管理 | M1 |
| `node:read` / `node:write` | 节点管理（含入站与 Host 增删改查）；链式出口（§5.21，M9） | M1 |
| `user:read` / `user:write` | 用户管理（含用量调整、下发状态与重试） | M2 |
| `plan:read` / `plan:write` | 套餐管理 | M2 |
| `setting:read` / `setting:write` | 系统 → 系统设置（含发测试邮件） | M4 |
| `content:read` / `content:write` | 公告、教程与下载、共享账号 | M4 |
| `ticket:read` / `ticket:write` | 工单（查看 / 回复与关闭） | M4 |
| `shop:read` / `shop:write` | 交易 → 商品定价（时长选项、上架、试用）、流量包、优惠码 | M5 |
| `finance:read` / `finance:write` | 交易 → 订单、余额流水、充值单、返利、收支统计（read）；生成 / 停用 / 查看充值码、调整用户余额（write） | M5 |
| `impersonate:write` | 用户管理 → 切换为用户身份（§5.17） | M5 |

邀请码的管理归 `user:read` / `user:write`。

### 4.1 授权规则（防垂直越权，R-N）

| R | 规则 |
|---|---|
| R1 | 管理接口按权限码鉴权；未登录 401 `unauthenticated`，缺权限码 403 `permission_denied`。 |
| R2 | 只能授予自己拥有的权限码：创建 / 修改角色时，权限集合必须是操作者权限的子集。 |
| R3 | 只能分配权限集合是自己子集的角色；`super_admin` 角色只能由 `super_admin` 分配或收回。 |
| R4 | 不能经管理员管理接口修改自己（角色、禁用状态），返回 409 `conflict`；改自己的口令允许。 |
| R5 | 系统中至少保留一个启用状态的 `super_admin`；会导致违反的禁用 / 改角色操作返回 409 `conflict`。 |
| R6 | 内置角色（`is_builtin`）不可删除、不可改权限；被管理员引用的角色不可删除（409）。 |
| R7 | 管理员被禁用或改密码时，其全部会话立即失效。 |

## 4.2 管理员会话与登录

| 项 | 约定 |
|---|---|
| 会话载体 | 服务端会话表 `admin_session`；Cookie `hub_admin_session` 只存随机 token（≥ 256 bit），库里只存其 SHA-256 |
| Cookie 属性 | HttpOnly、SameSite=Lax、Path=`/api/admin`；生产 Secure（配置 `auth.secureCookie`） |
| 有效期 | 空闲 2 小时过期（每次请求顺延，写库节流 1 分钟）；绝对 7 天过期；登出即删除 |
| CSRF | 每个会话一个随机 CSRF token；登录与 `GET /api/admin/auth/me` 返回；非 GET/HEAD 请求必须带 `X-CSRF-Token`，不符返回 403 `permission_denied` |
| 登录频控 | 同一用户名或同一 IP 15 分钟内失败 5 次即锁定 15 分钟，返回 429 `rate_limited`；锁定期间正确口令也拒绝 |
| 失败提示 | 用户名不存在、口令错误、账号禁用统一返回 401 `unauthenticated`“用户名或密码错误”，不暴露哪一项错 |
| 口令 | argon2id（m=19 MiB, t=2, p=1，OWASP 基线）；长度 12–128 字符 |
| 审计 | 登录成功 / 失败、登出、管理员与角色的增删改都写 `audit_log`，不记录口令与 token |

## 4.3 两步验证

管理员可自愿开启 TOTP 两步验证（RFC 6238：HMAC-SHA1、30 秒、6 位，兼容常见验证器 App）。

| 项 | 约定 |
|---|---|
| 开启 | ① `setup` 生成 160 bit 随机密钥，加密存入 `admin.totp_pending_enc`，返回 `otpauth://` 地址与 Base32 密钥（仅此一次）；② `enable` 提交当前验证码，校验通过后转存 `totp_secret_enc` 并清空待定密钥。重复 `setup` 覆盖待定密钥 |
| 登录 | 已开启的账号，口令正确但未带 `totpCode` 返回 401 `totp_required`（前端据此显示验证码输入框）；验证码错误按登录失败计入频控，提示统一为“验证码错误” |
| 时间窗 | 允许前后各 1 个 30 秒步长的时钟偏差 |
| 防重放 | 每个账号记录最近一次成功使用的步长 `totp_last_step`，同一或更早步长的验证码不再接受 |
| 关闭 | 本人提交当前验证码后关闭；遗失设备时由有 `admin:write` 的管理员按 R3 清除（不能对自己操作，R4），被清除者全部会话失效（R7 同理） |
| 存储 | 密钥用 AES-256-GCM 加密，主密钥来自环境变量 `HUB_ENCRYPTION_KEY`（Base64 的 32 字节），不入库、不入配置文件 |
| 审计 | `admin.totp_enable`、`admin.totp_disable`、`admin.totp_reset` |

## 5. 错误码表

信封 `{code, message, data}`，`code = "0"` 为成功。

| code | HTTP | 含义 |
|---|---|---|
| `0` | 200 | 成功 |
| `invalid_argument` | 400 | 参数校验失败 |
| `unauthenticated` | 401 | 未登录或会话过期 |
| `permission_denied` | 403 | 无权限码或越权访问他人数据 |
| `not_found` | 404 | 资源不存在 |
| `conflict` | 409 | 唯一性冲突或版本冲突 |
| `rate_limited` | 429 | 触发频控 |
| `totp_required` | 401 | 口令正确，但该账号已开启两步验证，需要再提交验证码 |
| `upstream_unavailable` | 502 | 面板不可达、拒绝 token 或返回异常（message 给出脱敏后的原因）；面板收到请求但拒绝执行（如端口冲突）按 400 `invalid_argument` 返回面板给出的原因 |
| `account_disabled` | 403 | 用户账号已被停用；客户后台只允许查看本人信息与退出 |
| `feature_disabled` | 403 | 该功能未开启（注册关闭、签到 / 工单未开、邮件未配置等），message 说明是哪一项 |
| `insufficient_balance` | 409 | 余额不足以支付本次下单；`data` 带还差多少（分），前端据此引导充值 |
| `internal` | 500 | 未分类内部错误（日志带上下文） |

## 5.1 服务器、入站与节点（M1）

| 项 | 约定 |
|---|---|
| 面板类型 | `server.provider_type`，当前只有 `xui`（3x-ui ≥ v3.0，Ruling-7、Ruling-8） |
| 接入信息 | 面板根地址（含 scheme、端口、web base path）+ API token（3x-ui 用 `admin` 范围）；token 以 `server:<id>:token` 为关联数据 AES-256-GCM 加密存储，只写不读 |
| TLS 校验 | `verify`（默认，系统 CA）/ `pin`（只认指定叶子证书 SHA-256，适合自签证书）/ `skip`（不校验，仅调试，界面明示风险）；`http://` 仅允许用于内网或本机调试 |
| 探测与同步 | 健康探测默认每 30 秒一次（T1–T3），入站同步默认每 5 分钟一次，另可手动“立即同步”；并发按服务器数限流 |
| 入站来源 | 面板是入站配置的事实来源（02 篇铁律二）。平台写入面板成功后立即回读并落库；缓存副本删除敏感字段（Reality 私钥、证书私钥内容、服务端口令），编辑时由 Provider 从面板原值补回 |
| 客户端字段 | 入站的 `clients` 列表不归入站管理（M2 由下发对账维护）；编辑入站时始终保留面板上的现有 clients |
| 漂移 | 每次平台写入后记录配置摘要 `synced_hash`（不含 clients 与流量计数）；同步时面板摘要与之不同即记 `drift_detected_at`，以面板为准覆盖缓存，管理员确认后清除标记。面板上已删除的入站标记 `is_missing`，不自动删除平台记录 |
| 缺失入站 | `is_missing` 是终态：同一面板标识再次出现时一律视为新入站、新建平台记录，旧记录不复活。缺失入站只能删除（只删平台记录，不再调用面板），编辑、启停、确认漂移、添加对外地址返回 409 |
| 面板标识复用 | 面板会把已删入站的标识分给新入站（3x-ui 的数字 id）。平台新建入站时，若该标识仍挂在一条未缺失的平台记录上，说明那条记录对应的入站已被删，先将其标记缺失再新建；同步时同一标识的协议变了，同样按“旧的缺失 + 新的新增”处理。旧记录的节点与节点组成员关系留在旧记录上，不转给新入站 |
| 删除入站 | 先删面板、再删平台记录及其节点；面板返回成功或“已不存在”都视为删除成功 |
| 删除对外地址 | 只删所点的那一个（入站 × 地址）。3x-ui 的 Host 组是“入站集合 × 地址集合”，删除时由 Provider 改写所在组：组里只剩这一对就删组；只涉及一个入站或一个地址就缩小组；否则拆成两组，被移到新组的地址保留原平台记录与节点。面板上已不存在的地址只删平台记录 |
| 节点 | 每个入站自动生成一个“直连”节点；入站上每个 Host 地址再各生成一个节点。节点有显示名、地区、标签、排序、启停，均只影响平台展示与派发，不写回面板 |
| 节点组 | 节点的命名集合，一个节点可属多个组；套餐按组授权（M2） |
| 入站表单 | 与 3x-ui 同构（Ruling-16）：基础（启用、备注、协议、监听地址、端口）/ 协议 / 传输 / 安全（无、TLS、Reality）/ 嗅探 / 高级 JSON。协议覆盖 Xray 内核的 vless、vmess、trojan、shadowsocks、hysteria、wireguard、http、mixed、tunnel；提交时以 protocol + config（settings / streamSettings / sniffing）写入面板。服务端模板（`vless-reality`、`vmess-ws`、`shadowsocks-2022`）保留给接口调用 |
| 入站密钥 | 照 3x-ui（Ruling-16）：表单显示私钥与口令。Reality x25519、ML-DSA-65、VLESS encryption 由面板生成（平台代理面板的生成接口）；UUID、Short ID、SS2022 密钥、WireGuard 密钥在浏览器用安全随机数生成。编辑时从面板实时读取完整配置（含密钥，不含 clients），每次读取记审计；平台缓存仍删除敏感字段（Ruling-14） |

## 5.2 用户、套餐与下发（M2）

| 项 | 约定 |
|---|---|
| 用户 | 用户名（登录客户后台用，3–64 位）、口令（argon2id，管理员设初始口令）、备注、所属套餐，以及从套餐拷来的额度、到期、IP 限制、周期重置；免费续期（每 N 天 / 每月几号 / 每周几，最多次数）自 M5 起只在用户上、由管理员在“改用量”里设置（Ruling-20）；一个用户只有一个套餐 |
| 套餐 | 名称、流量额度（字节，0 不限）、时长（天，0 不限；可选“首次使用后开始计时”）、节点组（多选）、同时在线 IP 数（0 不限）、周期流量重置（不重置 / 每小时 / 天 / 周 / 月，月度几号）、功能开关（客户端链式、自有落地，M6 起生效） |
| 分配与续费 | 见 U6。套餐改了不影响已分配的用户，直到再次分配、续费或购买。管理员手动分配不产生订单、不扣余额；用户自己买见 §5.13 |
| 用量 | 已用 = 各面板上行 + 下行之和，不设倍率。流量任务默认每分钟拉一次各面板 client 流量，按上次读数求增量累加；面板读数变小视为面板侧清零，增量取当前读数。按小时留用量明细（客户后台流量明细用，M3） |
| 管理员改用量 | 可直接清零已用、设置已用值、改额度、改到期、改 IP 限制（U7），每次记审计 |
| 授权 | 用户可用节点 = 套餐节点组里的节点，且节点启用、来源入站未缺失、所在服务器未停用；按入站去重得到期望的（用户, 入站）集合 |
| 下发 | 每个用户在每台面板上一个 client（email 见 §6），凭据（UUID、口令、SS2022 用户密钥等）由平台生成并在各面板一致；client 挂到该面板上所有被授权的入站。面板上的 client 不设额度与到期，配额与到期只由平台判定；用户非 `active` 时 client 禁用 |
| 对账 | 期望状态变更即触发，另每 5 分钟兜底一次。只管 email 符合平台规则的 client，面板上其它 client 不碰。按差异新建 / 挂载 / 卸载 / 启停 / 删除；同一面板的操作合并成批（禁用 client 会触发 Xray 重启）。结果写 `provision`，失败按指数退避重试，管理员可手动重试 |
| 删除用户 | 先删各面板上的 client，再删平台记录；面板不可达时记为待删除，恢复后由对账完成。没有任何面板 client 的用户当场删除平台记录；未关闭的工单在删除时一并删除，不等对账 |

## 5.3 终端用户会话与账号（M3）

规则与管理员侧（§4.2、§4.3）同构，实现复用；差异如下表。

| 项 | 约定 |
|---|---|
| 会话 | 会话表 `user_session`；Cookie `hub_user_session`，HttpOnly、SameSite=Lax、Path=`/api/user`，生产 Secure；库里只存 token 的 SHA-256 |
| 有效期 | 空闲 7 天过期（请求顺延，写库节流 1 分钟），绝对 30 天过期；登出即删除 |
| CSRF | 与 §4.2 相同：登录与 `GET /api/user/auth/me` 返回 token，非 GET/HEAD 请求必须带 `X-CSRF-Token` |
| 登录 | 用用户名或邮箱登录（M4）：先按用户名找，找不到且输入含 `@` 时按邮箱找；频控与失败提示同 §4.2（同一用户名或同一 IP 15 分钟 5 次失败锁 15 分钟，提示不区分哪一项错） |
| 口令 | argon2id；长度 8–128 字符。本人改口令须提交旧口令，成功后其余会话全部失效；管理员重置口令后该用户全部会话失效 |
| 两步验证 | 自愿开启，规则同 §4.3；关闭须提交当前验证码；遗失设备由有 `user:write` 的管理员清除，被清除者全部会话失效 |
| 归属（R8） | 用户接口的身份只取自会话，不接受请求中的用户 id；只能读写本人数据，访问他人资源一律 404 |
| 停用 | `disabled` 的用户可以登录，但除 `auth/me` 与登出外的接口返回 403 `account_disabled`；订阅只返回一条说明状态的信息节点 |
| 登录记录 | 每次登录成功 / 失败记 `user_login_log`（时间、IP、结果），本人可见最近 10 条，保留 90 天；不记口令与验证码 |
| 审计 | 管理员对用户的操作照旧写 `audit_log`；用户本人的操作（改口令、两步验证、重置订阅）写 `user_login_log` 之外的 `audit_log`，操作者记为该用户 |

## 5.4 订阅（M3）

| 项 | 约定 |
|---|---|
| 地址 | `GET /sub/{token}`，无需登录；每个用户一个 token，首次进入客户后台或创建用户时生成。库里存两份：`sub_token_hash`（SHA-256，用于查找）与 `sub_token_enc`（AES-256-GCM，关联数据 `end_user:<id>:sub`，用于在客户后台再次显示） |
| 重置 | 用户本人或有 `user:write` 的管理员可重置：换新 token，**同时轮换连接凭据**（UUID 与口令），旧地址与旧凭据立即失效并触发对账；客户端需重新导入。面板不可达时该面板的旧凭据在恢复后由对账换掉 |
| 格式 | `?format=` 取 `base64`（分享链接列表）/ `mihomo` / `singbox` / `xray`；未指定时按 User-Agent 判断：含 clash、mihomo、stash 用 `mihomo`，含 sing-box、SFA、SFI、SFM 用 `singbox`，其余用 `base64`。不认识的取值返回 400 |
| 节点来源 | 订阅不回源面板（02 篇铁律四）。对账时向面板取该 client 的分享链接，加密存入 `provision.links_enc`（关联数据 `provision:<id>:links`）；只在新建、换凭据、挂载变化、尚无链接，或该面板的入站 / 对外地址摘要变化时重取，取失败记该用户本轮下发失败并重试。面板生成的链接是节点参数的唯一来源，平台不自行拼装协议参数 |
| 节点与链接对应 | 同一服务器内：链接的（地址，端口）等于某个对外地址节点的，就对应该节点；其余链接，端口等于入站端口且地址不是该入站任何对外地址的，对应该入站的直连节点。直连节点对外用平台登记的服务器地址（面板给出的是它自己认定的主机名，不可靠）。面板只为有对外地址的入站输出对外地址链接，这类入站的直连节点没有链接、不输出。对应不上、节点或入站停用、不在用户授权范围内的链接不输出。输出名称用节点显示名，顺序按节点排序值、再按名称 |
| 统一模型 | 链接先解析为 `ProxyNode`（协议、地址、端口、凭据、传输、安全参数），再渲染各格式；解析不了的链接跳过并记日志（不含凭据）。覆盖 vless、vmess、trojan、shadowsocks、hysteria2 |
| 完整配置 | `mihomo` 与 `singbox` 输出可直接运行的完整配置：一个手动选择组、一个自动测速组；规则只有三类——私有网段直连、中国大陆地址直连、其余走代理。`xray` 输出一个数组，每个节点一份完整的 Xray 客户端配置（`remarks` 为节点名，形状与 3x-ui 的 JSON 订阅一致），说明节点与 hysteria2 不输出；`base64` 只有链接 |
| 用量信息 | 响应头 `Subscription-Userinfo: upload=0; download=<已用>; total=<额度>; expire=<到期秒数>`（不限则省略对应项）、`Profile-Update-Interval`、`Profile-Title`、`Content-Disposition` |
| 信息节点 | 可配置（默认开）：在节点前附两条不可连通的说明节点“剩余流量”“到期时间”。用户非 `active` 时不输出真实节点，只输出一条说明原因的信息节点 |
| 记录 | 每次成功拉取记 `subscribe_log`（时间、格式、IP、User-Agent 截断到 255 字符），默认保留 30 天；本人可见自己的，管理员凭 `user:read` 可查全部 |
| 频控 | 同一 token 每分钟 30 次、同一 IP 每分钟 60 次，超出返回 429；token 不存在返回 404，并按 IP 计入失败频控（15 分钟 20 次即锁 15 分钟），防枚举 |
| 设置 | 对外基地址、更新间隔（小时）、标题、信息节点开关、记录保留天数：M3 放配置文件 `subscription` 段，M4 起移入系统设置表由管理端修改 |
| 凭据处理 | 订阅地址与分享链接视同凭据：不进日志、不进审计详情；客户后台默认打码，点击才显示 / 复制 |

|---|---|
| 配置 | SMTP 主机、端口、账号、口令、发件人、加密方式（`starttls` / `tls` / `none`）全部走环境变量（`HUB_SMTP_*`，Ruling-24）。主机或发件人为空即“邮件不可用”：注册验证码、找回口令、换绑邮箱、公告群发、工单通知整体关闭，相关接口返回 403 `feature_disabled` |
| 发件箱 | 所有邮件先写 `mail_outbox` 再由后台任务发送，接口不等 SMTP。失败按指数退避重试，最多 5 次；正文加密存储（AES-256-GCM，关联数据 `mail_outbox:<随机键>`），发送成功或放弃后清空正文，只留收件人、主题、状态；记录保留 30 天 |
| 速率 | 全局按 `mail.ratePerMinute` 限速，验证码类邮件优先于群发 |
| 内容 | 模板内置在后端（纯文本 + 简单 HTML 两份），变量只做转义后的文本替换；不接受用户提供的 HTML |
| 测试 | `setting:write` 可向指定地址发一封测试邮件，直接返回 SMTP 结果（脱敏） |
| 日志 | 日志与审计不记邮件正文与验证码；收件人在日志里打码（`a***@example.com`） |

**邮箱验证码**（Ruling-23：注册、找回口令、换绑都用验证码，不发链接）

| 项 | 约定 |
|---|---|
| 形式 | 6 位数字，10 分钟有效；库里只存 HMAC-SHA256（密钥由主密钥派生），不存明文 |
| 用途 | `register` / `reset` / `bind`，互不通用；同一邮箱同一用途只有最新一条有效 |
| 校验 | 一条验证码最多校验 5 次，超出即作废；校验通过即作废（一次性） |
| 发码频控 | 同一邮箱每分钟 1 次、每小时 5 次；同一 IP 每小时 20 次；超出 429 |
| 不泄露存在性 | 找回口令的发码接口对不存在的邮箱同样返回成功，只是不发信 |

## 5.8 注册、邀请与账号自助（M4）

| 项 | 约定 |
|---|---|
| 注册方式 | `open`：任何人可注册，邀请码可选；`invite`：必须有有效邀请码；`closed`：返回 403 `feature_disabled`。管理员手动建号不受影响 |
| 注册字段 | 用户名（3–64 位字母、数字、`_`、`.`、`-`；自 M4 起新建用户名不再允许 `@`，存量保留）、邮箱（必填，≤ 254 字符，存小写，全站唯一）、口令（8–128）、邀请码（视方式）、邮箱验证码（`register.emailVerify` 生效时必填） |
| 邮箱域名 | 先过黑名单再过白名单，不通过返回 400，提示“该邮箱域名不支持注册” |
| 冲突 | 用户名或邮箱已被占用返回 409（注册表单无法避免暴露占用情况，靠频控约束）。邮箱不得与任何现有用户名相同（存量用户名可能含 `@`），注册与换绑时一并判重 |
| 频控 | 同一 IP 每小时成功注册 3 个、每小时提交 20 次；超出 429 |
| 注册结果 | 建用户（邮箱视为已验证，若未要求验证码则记为未验证）→ 记录邀请关系 → 若 `register.planId` 非 0 则分配该套餐并触发对账 → 直接登录（下发会话 Cookie） |
| 邀请码 | 10 位随机字母数字（去掉易混字符），不区分大小写。两类：个人码（每个用户一个，首次查看时生成，可重置，重置后旧码作废；次数上限取 `invite.userMaxUses`）与管理员码（自定可用次数、到期时间、备注，可停用）。使用一次计数加一，计数与上限的判断在同一事务内完成（并发注册不超发） |
| 邀请关系 | `end_user.invited_by`（邀请人，可空）与 `invite_code_id`；邀请人被删除后置空。本人可见“我邀请的人”列表（只显示打码用户名与注册时间）。返利见 §5.16 |
| 邮箱绑定 | 管理员建的用户可以没有邮箱。本人绑定 / 换绑：提交当前口令 + 发到新邮箱的 `bind` 验证码；管理员可直接改用户邮箱（视为已验证）。邮件不可用时本人不能自助换绑 |
| 找回口令 | ① 提交邮箱 → 发 `reset` 验证码（不存在的邮箱也返回成功）；② 提交邮箱 + 验证码 + 新口令 → 改口令并让该用户全部会话失效。**不关闭两步验证**，登录仍须验证码。没有邮箱或邮件不可用时只能找管理员重置 |
| 注销账号 | 本人提交当前口令（已开两步验证的另须验证码）后注销：按“删除用户”处理（§5.2），用户名与邮箱随即可被重新注册；未关闭的工单一并删除；剩余余额作废（§5.14），前端在确认框里写明 |
| 审计 | 注册、找回口令、换绑邮箱、注销、邀请码的生成 / 重置 / 停用都写 `audit_log`，不记口令与验证码 |

## 5.9 公告、教程与共享账号（M4）

三者都是“管理员维护、用户只读”，权限码 `content:*`。

| 项 | 约定 |
|---|---|
| 正文格式 | Markdown 源文本（≤ 20000 字符）。前端渲染时不执行原始 HTML，链接只允许 `http` / `https` / `mailto`（Ruling-25） |
| 公告 | 标题（1–100）、正文、置顶、弹窗、发布时间（空 = 草稿）。用户只见已发布的，置顶在前、新的在前；仪表盘显示最新一条，标了“弹窗”的最新一条在进入仪表盘时弹出，用户关闭后同一条不再弹（记在浏览器本地） |
| 公告群发 | 发布时可勾选“同时邮件通知”：给所有有已验证邮箱且未停用的用户各入一封发件箱邮件；每条公告只能群发一次。邮件不可用时不可勾选 |
| 教程与下载 | 按平台（`windows` / `macos` / `android` / `ios` / `linux` / `router`）分组的条目：客户端名、简介、下载链接（≤ 5 个，各含名称与 `https` 地址）、正文、排序、是否发布。用户页按平台分段，每篇教程带去仪表盘导入订阅的入口（订阅地址只在仪表盘出现，不写进教程正文） |
| 共享账号 | 名称、分类（1–32）、账号、口令、备注、排序、是否发布；可限定套餐（不选 = 所有有套餐的用户可见）。口令加密存储（AES-256-GCM，关联数据 `shared_account:<id>`）。只有 `active` 且符合套餐限定的用户能看到条目；列表不带口令，点“显示”才单独取，取一次记一条审计（不记口令）。`shared.enabled` 关闭时用户侧接口返回 403 `feature_disabled` |

## 5.10 工单（M4）

| 项 | 约定 |
|---|---|
| 状态 | `open`（等管理员回复）/ `answered`（等用户回复）/ `closed`。用户新建或回复 → `open`；管理员回复 → `answered`；双方都可关闭；用户回复已关闭的工单即重新打开 |

| 限制 | 每个用户未关闭的工单最多 5 张；每小时新建 5 张、回复 30 条，超出 429 |

| 通知 | 管理员回复后给用户的已验证邮箱发一封提醒（不含回复正文，只说“工单有新回复”）；用户新建 / 回复时若设了 `ticket.notifyEmail` 则通知该邮箱。邮件不可用时不通知 |
| 停用用户 | 按 §5.3，`disabled` 的用户不能使用工单 |

## 5.11 签到（M4）

| 项 | 约定 |
|---|---|
| 条件 | `checkin.enabled` 为真；用户有套餐、流量额度不是“不限”、状态为 `active` 或 `limited`。不满足返回 409 并说明原因 |
| 频率 | 每个用户每个自然日（`site.timezone`）一次；由 `(user_id, 日期)` 唯一约束保证，并发提交只有一次成功，其余返回 409“今天已经签到” |
| 奖励 | 在 `[checkin.minMb, checkin.maxMb]` 内均匀随机取整数 MB，加到当前流量额度上；与写签到记录在同一事务内完成。`limited` 的用户因此回到额度以内时状态重算为 `active` 并触发对账 |
| 与续费的关系 | 奖励加在当前额度上；续费、重新分配套餐或管理员改额度时额度被整体覆盖，此前的签到奖励不保留。周期流量重置只清已用，不动额度 |
| 记录 | `checkin_log`（日期、奖励字节数），本人可见最近 30 条 |

## 5.12 金额与商品（M5）

| 项 | 约定 |
|---|---|
| 金额 | 一律整数**分**（`BIGINT`），接口与库里都不出现小数；单币种，`shop.currency` 只决定前端显示的符号，不做换算。单价与单笔金额上限 99 999 999 分，余额上限 9 999 999 999 分；余额有 `CHECK (balance >= 0)` |
| 时长选项 | 套餐可售的规格：天数（1–3650）+ 价格（≥ 0）。同一套餐最多 6 个，天数不重复。流量额度取套餐的值；长周期里流量是否按月重置由套餐的“周期流量重置”决定（Ruling-29），前端据此显示“每月 X”或“有效期内共 X” |
| 套餐的售卖属性 | 是否上架、排序、卖点说明（纯文本，≤ 500 字符，一行一条）、是否试用。未上架或没有时长选项的套餐不出现在商店，但管理员仍可手动分配 |
| 试用 | 标了“试用”的套餐：每个用户终身只能下单一次（库唯一约束保证），且下单时不能持有未到期的其它套餐；不能用优惠码，不触发返利，不能开自动续费 |
| 流量包 | 名称、流量（字节）、价格、是否上架、排序。只加额度不改到期；和签到奖励一样加在当前额度上，续费 / 换购 / 管理员改额度时不保留（同 Ruling-26） |
| 免费分配 | `register.planId` 的注册赠送与管理员手动分配都不是订单，不计入收支 |

## 5.13 下单与订单（M5）

| 项 | 约定 |
|---|---|
| 支付方式 | **购买一律从余额扣款**（Ruling-28）。余额不足返回 409 `insufficient_balance` 并给出差额，不生成待支付订单；在线支付只用于给余额充值（§5.15） |
| 可买条件 | `shop.enabled` 为真；用户不是 `disabled`。套餐须上架且该时长选项存在；流量包须上架，且用户有套餐、额度不是“不限”、状态为 `active` 或 `limited` |
| 询价 | 下单前可询价：返回原价、优惠、应付、当前余额、差额与下单后的到期时间；询价不落库、不占优惠码次数 |
| 购买套餐 | 见 U11。同一套餐即续费：未到期从原到期日顺延、已到期从现在起算，已用清零，额度与 IP 限制恢复为套餐当前值。换成别的套餐：立即生效，到期 = 现在 + 天数，原套餐剩余时长作废、不折算（Ruling-30），前端下单前写明 |
| 购买流量包 | 见 U12。`limited` 的用户因此回到额度以内时状态重算为 `active` 并触发对账 |
| 原子性 | 一笔下单在同一事务内完成：锁用户行 → 校验 → 算价（含优惠码）→ 扣余额并写流水 → 写订单 → 应用套餐或流量包 → 记优惠码使用 → 记返利。任一步失败整体回滚；提交后触发对账 |
| 订单 | 订单号（`O` + 14 位时间 + 6 位随机数字，唯一）、用户、类型（`plan` / `traffic_pack` / `renew` 自动续费）、商品快照（套餐或流量包的名称、天数、流量、单价，JSON）、原价、优惠金额、实付、优惠码、创建时间。只有“已支付”一种状态：M5 不做退款与撤单，纠错由管理员调整余额并在流水里写明（Ruling-30） |
| 频控 | 每个用户每分钟下单 10 次、询价 60 次，超出 429 |
| 归属 | 用户只能看自己的订单（R8）；管理端 `finance:read` 可按用户、类型、时间筛选 |
| 用户删除后 | 订单、流水、充值单、返利记录保留用于对账：`user_id` 置空，另存下单时的用户名快照（Ruling-32） |

## 5.14 余额与流水（M5）

| 项 | 约定 |
|---|---|
| 变动入口 | 只有这几种，各对应一种流水类型：充值码 `topup_code`（+）、在线充值 `topup_online`（+）、购买 `purchase`（−）、自动续费 `renew`（−）、返利 `rebate`（+）、管理员调整 `admin_adjust`（±）、注销作废 `forfeit`（−） |
| 一致性 | 改余额与写流水在同一事务内，先 `SELECT … FOR UPDATE` 锁用户行；流水记变动金额（带符号）、变动后余额、关联对象（订单 / 充值码 / 充值单 / 返利）与备注。余额不会为负 |
| 管理员调整 | `finance:write`；金额（可正可负，结果不得为负）+ 必填备注（1–255），记审计。退款、补偿、纠错都走这里 |
| 注销 | 注销 / 删除用户时若余额 > 0：写一条 `forfeit` 流水把余额清零，然后按 §5.2 删除。余额不能提现、不能转给别人（Ruling-30） |
| 可见性 | 本人可看余额与自己的流水（分页）；管理端 `finance:read` 看全部 |

## 5.15 充值码、在线充值与优惠码（M5）

**充值码**

| 项 | 约定 |
|---|---|
| 生成 | `finance:write` 一次生成一批：面值（1–99 999 999 分）、数量（1–500）、到期时间（可空）、批次备注。码为 16 位（字符集同邀请码），显示时每 4 位一组 |
| 存储 | 码等同现金：库里只存 HMAC-SHA256（查找用，密钥由主密钥派生）与 AES-256-GCM 密文（关联数据 `topup_code:<随机键>`）（Ruling-31）。生成时一次性返回整批明文；之后列表只显示末 4 位，单条“查看”须 `finance:write` 并记审计 |
| 兑换 | 用户提交码 → 码存在、未用、未停用、未过期 → 余额加面值、写流水、码标记已用（使用人、时间），同一事务内完成，行加锁，一码只能用一次 |
| 防猜 | 每个用户每小时兑换失败 10 次、每个 IP 每小时 30 次后返回 429；失败提示不区分“不存在 / 已用 / 过期” |
| 停用 | 未使用的码可停用 / 启用、可删除；已使用的只能看 |

**在线充值**（Ruling-28：M5 只留接口，不带具体网关）

| 项 | 约定 |
|---|---|
| 抽象 | `manager/pay` 的 Gateway 接口：发起（返回跳转地址或二维码内容）、解析并验签回调。网关的密钥只走环境变量。没有配置任何网关时，充值入口不出现、发起接口返回 403 `feature_disabled` |
| 充值单 | 平台单号（唯一）、用户、网关、金额、状态 `pending` / `paid` / `expired`（30 分钟未支付）、网关交易号 |
| 入账幂等 | 回调验签通过后：按平台单号锁充值单，已是 `paid` 直接返回成功；金额与单据不一致则拒绝并记日志；否则置 `paid`、余额加金额、写流水。`(网关, 网关交易号)` 唯一，重复通知只入账一次 |

**优惠码**

| 项 | 约定 |
|---|---|
| 字段 | 码（4–32 位字母数字，存大写，唯一）、类型（`percent` 1–100 / `fixed` 分）、适用范围（全部套餐或指定套餐；是否适用于流量包）、最低消费、总次数上限（0 不限）、每人次数上限（默认 1）、生效与失效时间、是否停用、备注 |
| 计算 | `percent`：优惠 = 原价 × 百分比 ÷ 100，向下取整到分；`fixed`：优惠 = min(面额, 原价)。应付 = 原价 − 优惠，最低为 0 |
| 限制 | 试用套餐与自动续费不能用优惠码（Ruling-31）。次数判断与占用在下单事务内完成，优惠码行加锁，并发下单不超发 |
| 防猜 | 询价 / 下单时优惠码无效：每个用户每小时 20 次后返回 429；提示不区分“不存在 / 已用完 / 不适用” |
| 管理 | `shop:write` 增改停用；已被使用过的不可删除，只能停用 |

## 5.16 自动续费、提醒与返利（M5）

| 项 | 约定 |
|---|---|
| 自动续费 | 用户买过某套餐的某个时长选项后，可以开 / 关“到期自动续费”（记在用户上，连同上次购买的时长选项）。试用套餐不能开 |
| 续费时机 | 只在到期时刻尝试一次（Ruling-35）：先看管理员设的免费续期（U4），不适用再走 U10——该时长选项仍存在、套餐仍上架、余额 ≥ **当时售价** → 扣余额、生成 `renew` 订单、按 U6 从原到期日顺延。不用优惠码 |
| 顺延起点 | 到期后 24 小时以内续上的，从**原到期日**顺延（任务每分钟跑一次，不让用户因此少掉几十秒）；超过 24 小时（如服务停机多日）才续上的，从当前时刻起算 |
| 与面板的关系 | 续费排在到期判定之前：续上的用户不会先被标成 `expired` 再恢复，面板上的 client 不会因此被停用再启用 |
| 商店关闭期间 | `shop.enabled` 为假时不做自动续费，也不关闭用户的开关；用户照常到期，商店重新开启后的下一轮补上 |
| 续费失败 | 余额不足、套餐已下架或时长选项已删除：关闭自动续费，用户进入 `expired`，发“自动续费失败”邮件说明原因。之后充值不会补扣，用户需自己下单 |
| 续费成功 | 发“已自动续费”邮件（金额、新的到期时间、余额） |
| 到期提醒 | 到期前 `notify.expireDays` 天发一封提醒（每个到期时间只发一次）：写明到期时间、是否开了自动续费、余额是否够。免费续期的用户不提醒 |
| 流量提醒 | 剩余流量低于额度的 `notify.trafficPercent`% 时发一封；之后要等剩余流量回到阈值以上（清零、续费、买了流量包），再次低于阈值时才会再发 |
| 邮件条件 | 以上邮件只发给有已验证邮箱且未停用的用户；邮件不可用时都不发，续费逻辑照常执行。提醒在邮件不可用时不记“已提醒”，配好邮件后还能补发 |
| 返利 | `rebate.percent` > 0 时生效：被邀请人的订单（`plan` / `traffic_pack` / `renew`）实付 > 0，邀请人存在且未停用 → 邀请人余额加 实付 × 比例 ÷ 100（向下取整到分），写 `rebate` 记录与流水，与下单同一事务。`rebate.mode = first` 时只返被邀请人的第一笔实付 > 0 的订单；试用订单不返；邀请人余额已到上限时这笔返利作罢，不影响被邀请人的订单 |
| 返利去向 | 返利只进余额，只能在商店消费，不能提现（Ruling-34）。邀请页显示累计返利与返利记录（被邀请人用户名打码） |

## 5.17 切换为用户身份（M5）

| 项 | 约定 |
|---|---|
| 权限 | 独立权限码 `impersonate:write`，不随 `user:write` 附带；不能切换到 `disabled` 或待删除的用户 |
| 签发 | 管理端与客户门户是两个域名（Ruling-5），Cookie 不能跨域下发：管理端先签发一次性票据（≥ 128 bit 随机，60 秒有效，库里只存 SHA-256），再打开 `{site.portalUrl}/impersonate#ticket=…`；票据放在地址的 `#` 片段里，不会随请求发到服务器日志或 Referer |
| 会话 | 客户门户用票据换取一个带“代入”标记的用户会话，绝对有效期 30 分钟、不续期；票据用过即废，无效 / 过期 / 已用一律 400、不区分原因；管理员自己的管理端会话不受影响 |
| 只读 | 代入会话下，除“退出”外的非 GET 请求一律 403 `permission_denied`（Ruling-33）：不能改口令、邮箱、两步验证，不能下单、兑换、重置订阅、注销 |
| 可见范围 | 与该用户本人看到的相同；共享账号的口令、订阅地址照常按原规则（点击才取、记审计），审计里记实际操作的管理员 |
| 界面 | 客户后台顶部始终显示“正在以 xxx 的身份查看”与“退出”按钮 |
| 审计 | 开始与结束各记一条 `audit_log`（管理员、目标用户、IP）；代入会话的登录不写入用户的“最近登录” |

## 5.18 客户端链式（M6，M9 改为有序规则）

| 项 | 约定 |
|---|---|
| 形态 | 一条规则 = 一组起飞节点（多选）→ 一个落地（单选），规则之间有顺序（Ruling-46）。每个（起飞，落地）组合是一条两跳链路（Ruling-36）：客户端先连起飞节点，再经它连落地，出口 IP 是落地的。只在订阅里表达，平台不改任何面板配置（那是服务端链式，§5.19） |
| 开关 | 套餐的 `allow_client_chain` 决定能否使用，`allow_custom_node` 决定能否添加自己的出口（§5.21）。没有套餐或套餐没开时：菜单不显示；读取接口照常返回（带“未开通”标记与已有数据），新建 / 修改 / 调顺序返回 403 `feature_disabled`，删除始终允许 |
| 规则 | 字段：起飞节点（1–20 个）、落地（平台节点、平台出口、用户出口三选一，§5.21）、名称（可选，≤ 64 字符，缺省取落地的名称）、启用开关、顺序。起飞节点必须是本人当前可用的节点；落地是平台节点时不能同时出现在本条的起飞节点里。每个用户最多 20 条 |
| 协议限制 | 落地不能是 hysteria2 节点（基于 QUIC，经代理拨出不可靠），保存时返回 400；起飞不限。某个订阅格式不支持起飞或落地的协议 / 传输时，该格式里不输出这条链路 |
| 规则状态 | 计算值，不落库：`ok`（通畅）或 `blocked`（阻断）加原因——`plan`（套餐不支持链式，或落地是用户出口而套餐不支持）、`exit`（落地当前不可用：平台节点不可用，平台出口未授权 / 停用 / 不允许用于客户端，用户出口被管理员停用）。平台不探测连通性（Ruling-38），`ok` 只表示配置与授权成立 |
| 起飞节点状态 | 规则里每个起飞节点各有一个：`ok`、`unavailable`（该节点当前不可用）、`duplicate`（同一（起飞，落地）组合已在更靠前的规则里输出）。“当前可用”与节点列表（§5.5）同一口径：被授权且节点、入站、服务器都启用 |
| 阻断与删除 | 阻断的规则保留、不进订阅，条件恢复后自动生效（换套餐、节点临时停用都不丢规则）。平台节点被管理员删除时：作落地的规则一并删除；作起飞的从规则里移除，规则不剩起飞节点时一并删除。出口被删除时引用它的规则一并删除（界面先提示会删几条） |
| 订阅输出 | 启用且 `ok` 的规则按顺序、规则内按节点目录顺序，每个 `ok` 的起飞节点在 `mihomo`、`singbox`、`xray` 三种格式里各多输出一个节点，名称为“规则名 · 起飞节点名”，排在普通节点之后；进手动选择组，不进自动测速组。Mihomo：落地节点带 `dialer-proxy` 指向起飞节点名；sing-box：落地出站带 `detour` 指向起飞出站；Xray：每条链路单独一份完整配置，落地出站的 `streamSettings.sockopt.dialerProxy` 指向同一份配置里的起飞出站。`base64` 不输出链路。用户非 `active` 时与真实节点一样不输出 |
| 流量 | 链路流量在起飞面板上计入该用户用量；落地是平台节点时，落地面板也会计入，即同一份流量计两次（两台服务器都承载了它），页面上明示。落地是出口时，出口一侧的流量平台看不到 |
| 归属 | 规则与用户出口都属于用户本人（R8）：身份只取自会话，访问别人的一律 404 |
| 生命周期 | 用户被删除时规则与用户出口一并删除；重置订阅（轮换凭据）不影响规则；改规则后客户端下次更新订阅生效 |

## 5.19 服务端链式（M7，M9 改为有序规则并放开出口）

| 项 | 约定 |
|---|---|
| 形态 | 一条规则 = 一组起飞节点（多选）→ 一个落地（单选），规则之间有顺序（Ruling-46）。平台在每个起飞节点所在面板的 Xray 模板里加出站（连到落地）和路由（入站 = 起飞节点的入站，用户 = 本人在该面板上的 client email），于是本人连这些起飞节点的全部流量从落地出网；订阅与客户端配置不变（Ruling-39） |
| 开关与数量 | 套餐的 `allow_server_chain`（Ruling-41）；没开时与 §5.18 相同：读取照常、新建 / 修改 / 调顺序 403 `feature_disabled`、删除始终允许。每个用户最多 10 条，每条最多 20 个起飞节点 |
| 优先级 | 同一个起飞入站只能走一个出口：按顺序取第一条“启用且不阻断”的规则，更靠后的规则里这个起飞节点标 `shadowed`（被第 N 条覆盖）；靠前的规则阻断或停用后，自动落到后面的规则（Ruling-46）。按入站判断：两个节点共用一个入站（只是对外地址不同）时视为同一个起飞点 |
| 起飞与落地 | 起飞节点必须是本人当前可用的平台节点，且所在面板支持改内核配置（3x-ui 支持）。落地三选一（§5.21）：平台节点（不能是 hysteria2）、允许用于服务端的平台出口、用户出口（须通过下面的地址限制，Ruling-48） |
| 用户出口的地址限制 | 用于服务端链式时，入口服务器会去连用户填的地址，所以：IP 必须是公网单播地址（拒绝回环、私网、链路本地、运营商级 NAT、唯一本地、组播、文档与保留段、IPv4 映射的 IPv6）；域名由 hub-server 解析（只做 DNS 查询，不向该地址发起连接），全部解析结果都必须是公网地址，取其中一个固定下来存库，下发时出站地址写固定后的 IP，域名只留作 TLS 的 SNI 与 WebSocket 等的 Host。固定的 IP 每 6 小时复查一次：仍在解析结果里就不变，不在了才换；解析结果里出现非公网地址则规则阻断（原因 `unsafe`）。平台出口不受此限（管理员可能就是要指向入口服务器本机的出口） |
| 防环 | 落地是平台节点时，它不能同时是本人任何服务端规则的起飞节点；反过来，已作落地的节点也不能再选作起飞（Ruling-49）。用户出口固定后的 IP 不能等于平台任何服务器的地址（面板地址、节点对外地址及其解析结果），否则保存返回 400。经外部服务器绕回平台的环平台识别不了，流量照常计入本人用量 |
| 出站字段校验 | 用户出口用于服务端链式前逐字段校验：UUID 格式、REALITY 公钥为 32 字节、short id 为十六进制且不超过 16 位、Shadowsocks 加密方式、flow / 传输 / 安全类型 / 指纹 / alpn 都在白名单内；不通过则规则阻断（原因 `unsafe`），不进面板 |
| 落地凭据 | 落地是平台节点时，出站用本人在落地面板上的 client（与订阅里该节点的参数相同，取自分享链接），所以落地的授权、停用、到期、重置订阅轮换凭据都自动跟随；落地面板同样计入本人用量（同 §5.18 计两次）。落地是出口时用出口链接里的参数 |
| 规则状态 | `blocked` 的原因在 §5.18 的 `plan`、`exit` 之外多两个：`unsafe`（用户出口没通过地址限制或字段校验）、`quarantined`（被失败隔离，见下） |
| 起飞节点状态 | `unavailable`、`shadowed`，或下发情况：`applied`（生效：已在该面板上）、`pending`（下发中：还没写到面板，如刚改动、面板离线、落地凭据还没同步到）、`failed`（下发失败：该服务器最近一次下发被回滚） |
| 下发单位 | 以起飞服务器为单位整体对账（Ruling-40）：该服务器上全部生效的（规则，起飞入站）生成平台条目，与面板现状比较，不同才下发。一条规则在一台服务器上 = 一个出站 + 一条路由，路由的 `inboundTag` 是这条规则在这台服务器上生效的入站列表 |
| 平台条目 | 出站 tag 与路由规则的 `ruleTag` 都是 `hub-r{规则 id}`；路由规则插在 `api` 规则之后、其余规则之前，彼此按规则 id 升序（各条的入站 + 用户条件互不重叠，先后不影响结果）。平台只增删这类条目，不改模板的其它部分；模板里出现的其它 `hub-` 前缀条目（如手工复制的）一样视为平台所有，会被替换掉。路由里的用户 email 必须符合平台生成的格式（`u{用户 id}-{随机码}`），否则拒绝生成（Xray 的 `user` 条件支持 `regexp:` 前缀，不能让别的值进来） |
| 下发与回滚 | 见 §3 C1–C5：写入前加密备份整份模板（关联数据 `chain_apply:<服务器 id>:backup`）；写入后重启 Xray 并在 15 秒内确认运行，否则写回备份、再重启、记失败。重启会断开该服务器上的全部连接，所以同一台服务器两次下发至少间隔 60 秒（配置项，可调大），多次改动合并成一次 |
| 失败隔离 | 一次下发失败（C3）时，把本次相对上次成功新增或内容有变、且落地为用户出口的规则记为隔离（记下当时的内容指纹），下一轮不带它们重新下发，避免一个用户的坏配置拖住整台服务器（Ruling-49）。用户修改该规则或它引用的出口后指纹变化，隔离自动解除 |
| 频控 | 每个用户对服务端规则的写操作（新建、修改、删除、调顺序）合计每小时最多 10 次（配置项），超出返回 429 `rate_limited`；修改被服务端规则引用的用户出口的链接也计入（Ruling-49） |
| 检查频率 | 后台每 30 秒检查一次有规则或残留平台条目的在线服务器；规则增删改后立即触发一次（仍受最小间隔约束） |
| 并发写 | 模板是整份读改写，管理员在面板上同时改模板可能被覆盖或覆盖平台条目；后者会在下一轮被补回。页面提示不要在面板上手改 `hub-` 条目 |
| 管理端 | 服务器详情里看该服务器的下发状态、生效规则数、最近错误与时间，可点“重试”（`server:read` / `server:write`）；另有全站链式规则列表（只读，`server:read`），含类型、顺序、起飞节点、落地与状态，可按用户查找 |
| 归属与生命周期 | 同 §5.18：只属于本人，访问别人的 404；删用户、删节点、删出口时规则按 §5.18 处理，下一轮下发清掉面板上的条目；服务器被删除时它的下发记录一并删除（面板上残留的条目平台不再管理） |

| 粒度 | 收支统计（M5）增加按月汇总：按日最多 366 天，按月最多 24 个月；口径不变（充值入账、订单实付、返利、订单数） |

## 5.21 链式出口（M9）

| 项 | 约定 |
|---|---|
| 三种落地 | 链式规则的落地可以是：平台节点（本人可用的另一个节点）、平台出口（管理员添加）、用户出口（用户自己添加，即 M6 的自有落地节点）（Ruling-47）。后两种统称出口，存在同一张表里，`user_id` 为空的是平台出口 |
| 格式 | 一条分享链接（vless、vmess、trojan、shadowsocks）或 `socks5://[用户名:口令@]地址:端口`，长度 ≤ 2048 字符；保存时解析校验（协议受支持、地址非空、端口 1–65535），解析不了返回 400。出口只用作落地，不单独出现在订阅里 |
| 存储 | 链接含凭据：AES-256-GCM 加密存（关联数据 `custom_node:<id>:link`，沿用 M6 的写法，已有密文不用重加密），不进日志与审计；列表只返回名称、协议、地址与端口，原链接要单独请求才取（同 §5.4 凭据处理） |
| 平台出口 | 字段：名称（平台出口之间唯一，≤ 64 字符）、链接、备注（≤ 255 字符）、启用、可用于服务端链式、可用于客户端链式、所属节点组（多选）。用于客户端链式时凭据会写进用户的订阅、用户拿得走，所以两种用途分开勾选；用于服务端链式时凭据只留在面板上 |
| 平台出口的授权 | 用户能用某个平台出口 = 出口启用 + 出口属于本人套餐绑定的某个节点组 + 出口允许该类型 + 套餐开了该类型的链式开关。不受 `allow_custom_node` 影响。用户侧只返回 id、名称与协议，不返回地址与链接 |
| 用户出口 | 受套餐 `allow_custom_node` 约束，每人最多 10 个，名称在本人范围内唯一（≤ 64 字符，缺省取链接里的名称）。管理员可以停用：停用后引用它的规则阻断（原因 `exit`），用户看得到“已被管理员停用”，不能自己恢复，可以删除 |
| 管理端 | “链式出口”页（Ruling-50）：全部出口一张表，可按归属（平台 / 用户）、用户、关键字筛选，显示归属、协议、地址与端口、被几条规则引用、启用状态。平台出口可增删改，查看链接要单独点按钮并记审计；用户出口只能停用 / 启用与删除，不能查看或修改链接。读要 `node:read`，写与查看链接要 `node:write` |
| 删除 | 出口被删除（本人或管理员）时引用它的规则一并删除，界面先提示会删几条；平台出口被移出节点组或停用时规则不删，只是阻断 |
| 审计 | `chain_exit.create` / `update` / `delete` / `link_view`（平台出口）、`chain_exit.disable` / `enable` / `delete_user`（用户出口），详情不含链接 |

## 6. 编号与约定

- 面板上的 client email 由平台生成：`u{userId}-{6 位随机短码}`，同一用户在各面板一致；不得含用户真实邮箱或手机号。
- 平台在面板 Xray 模板里只增删 `hub-` 前缀的出站与路由规则（服务端链式，§5.19）：出站 tag 与路由 `ruleTag` 均为 `hub-r{规则 id}`。
- 客户端链式在完整配置里的命名：链路节点用规则名（与普通节点重名时照常追加序号）；Xray 配置里入口出站的 tag 固定为 `chain-entry`。
- 邀请码：10 位，字符集去掉 `0O1IL`，存大写；邮箱一律存小写并按小写判重。
- 订阅 token：≥ 128 bit 随机，URL 安全 Base64；可重置，重置后旧 token 立即失效（§5.4）。
- 订单号 `O` + `yyyyMMddHHmmss`（UTC）+ 6 位随机数字；充值单号同形，前缀 `P`。充值码 16 位、优惠码 4–32 位，字符集与大小写规则同邀请码。
