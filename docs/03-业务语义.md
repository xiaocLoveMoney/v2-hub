# 03 · 业务语义（唯一权威；改动先改本篇再改代码）

> 脚手架阶段只钉死术语与框架；状态机、权限码、错误码随各里程碑补全，补一条登记一条。

## 1. 领域模型与术语

| 术语 | 定义 | 出现在 |
|---|---|---|
| 管理员 admin | 登录管理端的人；权限来自所属角色 | `admin`、`admin_role` |
| 角色 role / 权限码 permission | RBAC；权限码与管理端菜单、接口一一对应 | `role`、`permission`、`role_permission` |
| 用户 user | 终端用户（单层模型，Ruling-11），由管理员创建，登录客户后台 | `user`（M2） |
| 服务器 server | 一台装了 3x-ui 的机器在平台上的登记；`provider_type` 区分面板实现 | `server`（M1） |
| 入站 inbound | 面板上的一个监听配置（协议 + 端口 + 传输 + 安全）；面板是事实来源 | `inbound`（M1） |
| Host / 端点 endpoint | 入站对外地址的覆盖（如 CDN 域名）；一个入站可有多个 | 3x-ui hosts |
| 节点 node | 面向用户的可选线路 = 服务器 × 入站 × 端点；有显示名、地区、标签、排序 | `node`（M1） |
| 节点组 node group | 节点集合，套餐按组授权 | `node_group`（M1） |
| 套餐 plan | 流量、时长、节点组、功能开关（链式、自有落地）的模板 | `plan`（M2） |
| 下发 provision | 用户在某面板上对应的 client 及对账状态 | `provision`（M2） |
| 订阅 subscription | `/sub/{token}`，按格式渲染用户全部可用节点 | `sub_token`（M3） |
| 客户端链式 | 只在订阅里表达的入口 → 落地链路 | `chain_rule.kind=client`（M4） |
| 服务端链式 | 改入口面板 Xray 出站与路由实现的链路 | `chain_rule.kind=server`（M5） |
| 漂移 drift | 面板侧被直接修改，导致与平台缓存不一致 | 同步任务（M1） |

## 2. 状态机

**服务器连接状态** `server.status`：`unknown`（刚接入未探测）/ `online` / `offline`（网络不通、超时、5xx）/ `auth_failed`（面板返回 401/403，token 失效或被删）。

（M2 补：用户状态 active / limited / expired / disabled；下发状态 pending / synced / failed。）

## 3. 转移表（T-N，代码里的表驱动实现与本表逐行对应）

| T | From | 触发 | 守卫 | To | 副作用 |
|---|---|---|---|---|---|
| T1 | 任意 | 探测成功 | — | `online` | 记录面板版本、面板 GUID、资源快照、`last_seen_at`；清空 `last_error` |
| T2 | 任意 | 探测失败：网络 / 超时 / 5xx / 响应无法解析 | — | `offline` | 记录脱敏后的 `last_error`；不清空已缓存入站 |
| T3 | 任意 | 探测失败：面板返回 401/403 | — | `auth_failed` | 同 T2；需管理员更新 token |
| T4 | 任意 | 管理员禁用服务器 | — | 状态不变 | 停止探测与同步；节点不再参与派发（M2） |

## 4. 权限码表

命名 `<资源>:<动作>`，动作只有 `read` / `write`；`write` 不隐含 `read`，角色需同时授予。
内置角色 `super_admin` **隐式拥有全部权限码**（代码判定，不依赖 `role_permission` 行），新增权限码无需回填。
权限码清单以本表为准，`init.sql` 的种子数据与代码常量逐行对应。

| 权限码 | 对应菜单 / 接口 | 里程碑 |
|---|---|---|
| `admin:read` / `admin:write` | 系统 → 管理员与角色 | M0 |
| `audit:read` | 系统 → 审计日志 | M0 |
| `server:read` / `server:write` | 服务器管理 | M1 |
| `node:read` / `node:write` | 节点管理（含入站与 Host 增删改查） | M1 |

### 4.1 授权规则（防垂直越权，R-N）

| R | 规则 |
|---|---|
| R1 | 管理接口按权限码鉴权；未登录 401 `unauthenticated`，缺权限码 403 `permission_denied`。 |
| R2 | 只能授予自己拥有的权限码：创建 / 修改角色时，权限集合必须是操作者权限的子集。 |
| R3 | 只能分配权限集合是自己子集的角色；`super_admin` 角色只能由 `super_admin` 分配或收回。 |
| R4 | 不能经管理员管理接口修改自己（角色、禁用状态），返回 409 `conflict`；改自己的口令允许。 |
| R5 | 系统中至少保留一个启用状态的 `super_admin`；会导致违反的禁用 / 改角色操作返回 409 `conflict`。 |
| R6 | 内置角色（`is_builtin`）不可删除、不可改权限；被管理员引用的角色不可删除（409）。 |
| R7 | 管理员被禁用或改密码时，其全部会话立即失效。 |

## 4.2 管理员会话与登录

| 项 | 约定 |
|---|---|
| 会话载体 | 服务端会话表 `admin_session`；Cookie `hub_admin_session` 只存随机 token（≥ 256 bit），库里只存其 SHA-256 |
| Cookie 属性 | HttpOnly、SameSite=Lax、Path=`/api/admin`；生产 Secure（配置 `auth.secureCookie`） |
| 有效期 | 空闲 2 小时过期（每次请求顺延，写库节流 1 分钟）；绝对 7 天过期；登出即删除 |
| CSRF | 每个会话一个随机 CSRF token；登录与 `GET /api/admin/auth/me` 返回；非 GET/HEAD 请求必须带 `X-CSRF-Token`，不符返回 403 `permission_denied` |
| 登录频控 | 同一用户名或同一 IP 15 分钟内失败 5 次即锁定 15 分钟，返回 429 `rate_limited`；锁定期间正确口令也拒绝 |
| 失败提示 | 用户名不存在、口令错误、账号禁用统一返回 401 `unauthenticated`“用户名或密码错误”，不暴露哪一项错 |
| 口令 | argon2id（m=19 MiB, t=2, p=1，OWASP 基线）；长度 12–128 字符 |
| 审计 | 登录成功 / 失败、登出、管理员与角色的增删改都写 `audit_log`，不记录口令与 token |

## 4.3 两步验证

管理员可自愿开启 TOTP 两步验证（RFC 6238：HMAC-SHA1、30 秒、6 位，兼容常见验证器 App）。

| 项 | 约定 |
|---|---|
| 开启 | ① `setup` 生成 160 bit 随机密钥，加密存入 `admin.totp_pending_enc`，返回 `otpauth://` 地址与 Base32 密钥（仅此一次）；② `enable` 提交当前验证码，校验通过后转存 `totp_secret_enc` 并清空待定密钥。重复 `setup` 覆盖待定密钥 |
| 登录 | 已开启的账号，口令正确但未带 `totpCode` 返回 401 `totp_required`（前端据此显示验证码输入框）；验证码错误按登录失败计入频控，提示统一为“验证码错误” |
| 时间窗 | 允许前后各 1 个 30 秒步长的时钟偏差 |
| 防重放 | 每个账号记录最近一次成功使用的步长 `totp_last_step`，同一或更早步长的验证码不再接受 |
| 关闭 | 本人提交当前验证码后关闭；遗失设备时由有 `admin:write` 的管理员按 R3 清除（不能对自己操作，R4），被清除者全部会话失效（R7 同理） |
| 存储 | 密钥用 AES-256-GCM 加密，主密钥来自环境变量 `HUB_ENCRYPTION_KEY`（Base64 的 32 字节），不入库、不入配置文件 |
| 审计 | `admin.totp_enable`、`admin.totp_disable`、`admin.totp_reset` |

## 5. 错误码表

信封 `{code, message, data}`，`code = "0"` 为成功。

| code | HTTP | 含义 |
|---|---|---|
| `0` | 200 | 成功 |
| `invalid_argument` | 400 | 参数校验失败 |
| `unauthenticated` | 401 | 未登录或会话过期 |
| `permission_denied` | 403 | 无权限码或越权访问他人数据 |
| `not_found` | 404 | 资源不存在 |
| `conflict` | 409 | 唯一性冲突或版本冲突 |
| `rate_limited` | 429 | 触发频控 |
| `totp_required` | 401 | 口令正确，但该账号已开启两步验证，需要再提交验证码 |
| `upstream_unavailable` | 502 | 面板不可达、拒绝 token 或返回异常（message 给出脱敏后的原因）；面板收到请求但拒绝执行（如端口冲突）按 400 `invalid_argument` 返回面板给出的原因 |
| `internal` | 500 | 未分类内部错误（日志带上下文） |

## 5.1 服务器、入站与节点（M1）

| 项 | 约定 |
|---|---|
| 面板类型 | `server.provider_type`，当前只有 `xui`（3x-ui ≥ v3.0，Ruling-7、Ruling-8） |
| 接入信息 | 面板根地址（含 scheme、端口、web base path）+ API token（3x-ui 用 `admin` 范围）；token 以 `server:<id>:token` 为关联数据 AES-256-GCM 加密存储，只写不读 |
| TLS 校验 | `verify`（默认，系统 CA）/ `pin`（只认指定叶子证书 SHA-256，适合自签证书）/ `skip`（不校验，仅调试，界面明示风险）；`http://` 仅允许用于内网或本机调试 |
| 探测与同步 | 健康探测默认每 30 秒一次（T1–T3），入站同步默认每 5 分钟一次，另可手动“立即同步”；并发按服务器数限流 |
| 入站来源 | 面板是入站配置的事实来源（02 篇铁律二）。平台写入面板成功后立即回读并落库；缓存副本删除敏感字段（Reality 私钥、证书私钥内容、服务端口令），编辑时由 Provider 从面板原值补回 |
| 客户端字段 | 入站的 `clients` 列表不归入站管理（M2 由下发对账维护）；编辑入站时始终保留面板上的现有 clients |
| 漂移 | 每次平台写入后记录配置摘要 `synced_hash`（不含 clients 与流量计数）；同步时面板摘要与之不同即记 `drift_detected_at`，以面板为准覆盖缓存，管理员确认后清除标记。面板上已删除的入站标记 `is_missing`，不自动删除平台记录 |
| 删除入站 | 先删面板、再删平台记录及其节点；面板返回成功或“已不存在”都视为删除成功 |
| 节点 | 每个入站自动生成一个“直连”节点；入站上每个 Host 地址再各生成一个节点。节点有显示名、地区、标签、排序、启停，均只影响平台展示与派发，不写回面板 |
| 节点组 | 节点的命名集合，一个节点可属多个组；套餐按组授权（M2） |
| 入站模板 | 平台内置 `vless-reality`、`vmess-ws`、`shadowsocks-2022` 三个模板，密钥（Reality x25519、UUID、SS2022 服务端密钥）在 hub-server 生成，不经浏览器；其余协议用“高级 JSON”直接提交面板配置 |

## 6. 编号与约定

- 面板上的 client email 由平台生成：`u{userId}-{6 位随机短码}`，同一用户在各面板一致；不得含用户真实邮箱或手机号。
- 平台在面板 Xray 配置里只增删 `hub-` 前缀的出站与路由规则（服务端链式，M5）。
- 订阅 token：≥ 128 bit 随机，URL 安全 Base64；可重置，重置后旧 token 立即失效。
