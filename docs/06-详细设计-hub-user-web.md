# 06 · 详细设计 · hub-user-web

> 负责人：@xiaoclux。职责：客户门户与客户后台。契约：`hub-api.yaml` 的 `/api/user`。
> 功能与界面形式参考 SSPanel-Uim Malio，自行实现、不搬其代码（Ruling-17、Ruling-21）。

## 1. 目录结构

```
v2-hub-user-web/
├── src/
│   ├── api/            # client.ts（openapi-fetch + CSRF）、generated/（由 hub-api.yaml 生成）
│   ├── auth/           # 会话上下文（React Context）
│   ├── hooks/          # use-remote 等，与管理端同构
│   ├── styles/         # tokens.css（设计变量）、base.css、各组件样式
│   ├── components/     # 设计系统组件（见 §4）
│   ├── layout/         # 外壳：侧栏、顶栏、色带、页脚
│   ├── pages/          # 一个菜单项一个目录
│   ├── menu.tsx        # 菜单表，同时驱动侧栏与路由守卫
│   └── routes.tsx
└── vite.config.ts      # 开发端口 5174，/api、/sub 代理到 8080
```

## 2. 模块划分与依赖方向

`pages → components → api`；页面不直接 `fetch`。不 import admin-web 的代码，工程做法（接口封装、
`use-remote`、会话上下文、菜单表）照管理端同样写一份。不引入组件库（Ruling-21）；图表、二维码、图标、国旗
各选一个小库，版本在 M3 开工时查文档确定并记入《任务与边界》。

## 3. 关键不变式

1. 菜单按系统设置开关与用户状态显示（未购买、已到期、功能关闭时不出现用不了的入口）；后端仍做最终鉴权与归属校验。
2. 订阅地址与分享链接属于凭据：默认打码，用户主动点击才显示 / 复制；不进埋点与日志。
3. 订阅内容只由 hub-server 渲染，前端只展示地址、二维码与各客户端的导入入口。
4. 金额一律用整数分运算与传输，只在显示时格式化。
5. 危险操作（重置订阅、注销账号、关闭两步验证）统一二次确认；提示统一走一个提示组件。

M4 的做法（docs/03 §5.6–§5.11）：

- 站点信息：启动时取一次 `/api/user/site`（未登录可读），决定登录页是否显示“注册”“找回密码”入口、注册表单要不要邀请码与邮箱验证码，
  以及菜单里签到、工单、共享账号是否出现；取不到时按全部关闭处理。
- 菜单顺序（M10 补充，Ruling-57）：每个菜单项带一个菜单键（docs/03 §5.6 菜单键目录），侧栏按站点信息里的 `menuOrder` 排序，先排序再按分组切开；取不到时按默认顺序。
- 注册、找回密码与登录共用登录外壳（`pages/auth/AuthShell.tsx`，M10 补充改版）：整页铺一张浅色插画背景（主体在右侧），顶栏左边品牌图标与站点名、右边语言切换；表单卡片在左侧居中偏左，卡片右边是站点名、标语与三条功能亮点；底部一行版权。窄屏（< 900px）只留卡片，插画仍作背景。插画为自制位图（`src/assets/auth-bg.webp`），不用第三方素材。
- 注册、找回密码与登录共用这个外壳。注册链接可带 `?code=` 预填邀请码；“发送验证码”按钮点后 60 秒内不可再点；注册成功即登录。
  找回密码成功后回登录页，不自动登录（两步验证不因此关闭，Ruling-23）。
- Markdown（公告、教程）用 react-markdown 渲染成 React 元素：不解析原始 HTML（Ruling-25）、不用 `innerHTML`，链接一律新窗口打开并带
  `rel="noopener noreferrer"`，危险协议由库默认的地址过滤去掉。
- 弹窗公告：进入仪表盘时弹出最新一条标了“弹窗”的公告；关闭后把该公告的 id 记在 `localStorage`（只存 id，不属凭据），同一条不再弹。
- 共享账号的密码与工单内容都不进 `localStorage`、不进日志。

M5 的做法（docs/03 §5.12–§5.17）：

- 金额：接口里一律是整数分，前端只在显示时按站点信息里的币种格式化（`src/money.ts`），不做加减乘除；应付、优惠、差额全部取询价接口的结果。
- 商店：每个套餐一张价格卡（卖点、流量、设备数、节点数），卡内用分段选择块选时长；点购买打开账单式结算框——
  每次选项或优惠码变化都重新询价，逐行列出原价、优惠、应付、余额与“还需充值”；续费、换购、流量包各自写明后果
  （续费清零已用、换购作废原剩余时长、流量包续费后不保留）。余额不足时确认按钮换成“去充值”。
- 我的钱包：余额 Hero 卡、兑换充值码、在线充值（站点配了网关才出现）、自动续费开关与续费对象、余额流水与订单两张分页表。
- 仪表盘第四张统计卡在商店开启时改为余额；注销账号的确认框写明剩余余额会作废。
- 切换为用户身份：独立页面 `/impersonate` 从地址的 `#` 片段里取票据、兑换成会话后立即用 `replace` 跳到仪表盘，票据不留在地址栏与历史记录里；
  代入会话期间外壳顶部固定显示“正在以 xxx 的身份查看（只读）”与退出按钮，所有会写数据的按钮照常显示但提交会被后端拒绝。

M6 的做法（docs/03 §5.18，Ruling-36 – Ruling-38）：

- 菜单：会话里 `features.clientChain` 为真才显示“链式代理”。页面本身对任何已登录用户可访问（套餐降级后从地址进入仍能查看与删除），
  开关关着时顶部给警告横幅并禁用新建；阻断的规则不进订阅，不处理也无副作用。
- 页面一个接口取全：`GET /api/user/chain` 返回开关、上限、规则、自有节点与可选入口 / 落地节点；任何写操作成功后整体重取。
- 规则表：名称、入口 → 落地（落地带“自有”徽章与协议）、状态药丸（通畅 / 阻断 + 原因：套餐不允许、入口不可用、落地不可用）、
  启用开关（即时保存）、改名、删除。阻断的规则保留，条件恢复后自动通畅，页面写明这一点。
- 新建规则：模态框里两个下拉——入口取 `nodes`，落地分组列出“平台节点”（排除所选入口与 hysteria 类）和“自有节点”；名称可空，
  空时显示默认名“入口 → 落地”。达到 20 条上限时新建按钮禁用并说明。
- 自有落地节点卡：列表只显示名称、协议、地址:端口与被引用次数；原链接不在列表里，点“查看链接”才单独请求；
  添加 / 更换链接用多行输入框粘贴分享链接或 `socks5://`；删除前若被规则引用，确认框写明会连带删除几条规则。
  `features.customNode` 为假时只读（可删除），卡片顶部说明原因。
- 说明卡：Mihomo、sing-box、Xray JSON 订阅带链路，Base64 不带；链路只出现在手动选择组；落地是平台节点时流量在入口与落地各计一次；
  平台不探测连通性，也不连接用户填写的地址。
- 链接内容不进 `localStorage`、不进日志；查看链接的结果只存在组件状态里，关闭即丢弃。

M7 的做法（docs/03 §5.19，Ruling-39 – Ruling-41）：

- 菜单：`features.clientChain` 或 `features.serverChain` 任一为真就显示“链式代理”；页面分“客户端链式”“服务端链式”两个区，各自按开关给提示。
- 服务端规则表：入口、落地、状态药丸——阻断（带原因）、已停用，或下发情况（生效 / 下发中 / 下发失败）；启用开关即时保存；删除。
  “下发中”可能持续一两分钟（同一台服务器两次下发至少隔 60 秒），页面写明；有规则处于下发中时每 15 秒自动刷新一次，页面卸载即停。
- 新建：入口只列 `canBeServerEntry` 的节点、且排除已有服务端规则的入口；落地列 `canBeExit` 且不同于入口的节点；没有自有节点选项。
- 说明卡补一句：服务端链式不改订阅，连入口节点即经落地出网；入口与落地两边都计流量。

链路示意卡（M10 补充）：页面最下方一张“链路示意”卡，跟随当前页签，把规则画成“我的设备 → 起飞节点 → 落地”三列积木，用平滑曲线相连。
设备块显示仪表盘接口的在线设备数（取不到写“未知”）；起飞节点按节点去重、落地按“类别 + id”去重，同一对起飞与落地只画一条线。
生效的连线（规则通畅且已启用，起飞节点为生效 / 下发中 / 可用）画实线并带流动效果，其余（阻断、停用、被覆盖、重复、不可用、下发失败）画灰色虚线；
设备到起飞节点的线随该节点是否有生效的连线。纯前端按已有数据绘制，不新增接口；系统减少动态效果时不流动；窄屏横向滚动。

M9 的做法（docs/03 §5.18、§5.19、§5.21，Ruling-46 – Ruling-49），取代上面 M6 / M7 里规则表与新建的写法：

- 页面两个页签：“服务端链式”“客户端链式”，各是一张有序的规则列表；页签按 `features.serverChain` / `features.clientChain` 显示，都关时仍可查看与删除。
- 规则行：序号、起飞节点（一组药丸，每个带自己的状态：生效 / 下发中 / 下发失败 / 被第 N 条覆盖 / 不可用 / 重复）、落地（带类别徽章：平台出口、我的出口、平台节点）、
  规则状态（通畅、阻断与原因、已停用）、启用开关、上移 / 下移、编辑、删除。顺序即优先级，页面写明“越靠前越优先”。
- 新建 / 编辑：模态框里“起飞节点”是下拉多选（自写组件 `components/MultiSelect.tsx`：按钮展开列表、复选、键盘可操作、点外面收起），
  “落地出口”是分组下拉单选（平台出口、我的出口、平台节点）；不可选的项置灰并写原因（已作落地、不支持改内核配置、hysteria 类）。名称可空。
- 调顺序：上移 / 下移按钮，点一次提交一次（`PUT /api/user/chain/routes/order`），成功后整体重取。不引入拖拽库。
- “我的出口”卡：沿用自有落地节点卡，改名；被管理员停用的行标“已被管理员停用”。用于服务端链式的限制（只许公网地址）写在添加框的说明里。
- 出口的添加 / 编辑弹窗（2026-11-14 补）：两种填法，“表单”与“分享链接”，可来回切换——切到表单时把链接解析进表单，切到链接时由表单拼出链接；
  提交的始终是一条分享链接，接口与存储格式不变（docs/03 §5.21）。表单参照 3x-ui 的出站表单：协议（vless / vmess / trojan / shadowsocks / socks）、
  地址、端口、按协议的凭据（ID 与 flow、加密方式、密码、用户名）、传输（RAW / WebSocket / gRPC / HTTPUpgrade / XHTTP 及其 Host、路径、serviceName、模式）、
  安全（无 / TLS / Reality 及其 SNI、指纹、ALPN、允许不安全、公钥、Short ID、SpiderX）。只列平台生成出站时会用到的字段（docs/03 §5.19 出站字段校验），
  3x-ui 表单里的发送通过、目标解析策略、反向标签、Sockopts、TCP Masks、Mux、HTTP 混淆不提供。表单表达不了的链接（hysteria2、带 HTTP 伪装的）只能用链接方式。
  编辑时默认不改连接参数，点“修改连接参数”才取一次现有链接填进表单；链接与表单内容只留在弹窗的内存里，关闭即丢弃。前端只做必填与格式提示，取值是否合法以后端为准。
- 出口的协议加 HTTP、HTTPS（M10，Ruling-51）：HTTPS 多 SNI 与“允许不安全”两项，链接形状 `http(s)://[用户名:密码@]地址:端口`。
- “测试延迟”（M10，Ruling-52）：每个出口一个按钮，展开后选起点节点（本人可用、面板支持的节点）与方式（TCP / HTTP / 真实延迟），
  显示延迟、HTTP 状态与出口 IP；失败时按原因大类给一句说明和排查提示（Ruling-56，中英文案在 `src/i18n/`），`unknown` 才说“连接失败或超时”。结果只留在页面内存里。被频控（429）、服务器占用（409）、地址不允许（400）各有说明。
- 服务端页签有下发中的起飞节点时每 15 秒自动刷新；写操作被频控（429）时提示稍后再试。
- 说明卡：两种链式的区别、优先级规则、流量计两次、服务端链式每次改动会让起飞服务器上的连接断一下。

M8 的做法（docs/03 §5.20，Ruling-44、Ruling-45）：

- 落地页：未登录访问根地址且站点信息里 `landing.enabled` 为真时，外壳不跳登录页，改为渲染落地页；其它地址照旧跳登录页。
  页面是顶栏（站点名、登录、注册）+ 主色 Hero（标题取 `landing.headline`，空则用站点名；介绍按 Markdown 组件渲染）+
  在售套餐卡（`GET /api/user/site/plans`，空列表时整段不显示；卡内列出流量、设备数、节点数与各时长价格，按钮“购买”去注册或登录）。
  注册按钮按注册方式显示（关闭时不出现）。已登录用户访问根地址直接进仪表盘。
- 客服按钮：`support.url` 非空时，落地页、登录 / 注册 / 找回密码页与已登录外壳右下角固定一个圆形按钮，文字取 `support.label`，
  `<a target="_blank" rel="noopener noreferrer">` 打开；前端再校验一次必须以 `https://` 开头，不是就不显示。不加载任何第三方脚本。
- 中英双语：自写一个很小的 i18n 层，不引入库。`src/i18n/messages/zh.ts` 是词条的唯一来源（扁平键，`{name}` 占位），
  `en.ts` 的类型要求与 zh 键完全一致，缺词条编译不过；`useI18n()` 给出 `locale`、`setLocale` 与 `t(key, vars)`。
  首次按 `navigator.language`（`zh*` 用中文，其余英文），选择记在 `localStorage` 的 `hub.locale`（只是偏好，读写失败按默认）；
  切换同时改 `<html lang>`。切换入口在已登录外壳页脚、登录外壳顶栏与落地页底部。
- 模块级的标签表（状态、原因、格式名等）改为存词条键，渲染时再 `t()`；菜单表同理。
- 格式化：日期、时间、流量单位、金额的函数都接收语言标签（`zh-CN` / `en-US`），由页面从 `useI18n()` 取；金额币种仍取站点信息。
- 错误：中文界面原样显示后端说明；英文界面按错误码查通用英文说明（未知错误码用“请求失败”），后端的中文说明放在括号里附在后面。
- 不翻译：站点名、公告、教程、套餐名与卖点、落地页介绍、工单内容、节点名，以及后端生成的文字。
- 测试夹具默认中文，原有用例不改断言；另加英文渲染、切换语言与错误码英文说明的用例。
