# 05 · 详细设计 · hub-admin-web

> 负责人：@xiaoclux。职责：管理门户（登录 + 总览大盘）与管理端。契约：`hub-api.yaml` 的 `/api/admin`。

## 1. 目录结构

```
v2-hub-admin-web/
├── src/
│   ├── api/            # client.ts（openapi-fetch + CSRF）、generated/（由 hub-api.yaml 生成）
│   ├── auth/           # 会话上下文
│   ├── hooks/          # use-remote、use-open-generation
│   ├── layout/         # AdminLayout
│   ├── pages/          # panel/、users/、system/ 等
│   ├── menu.tsx        # 菜单表（驱动左侧菜单与路由守卫）
│   ├── routes.tsx
│   ├── App.tsx         # ConfigProvider（主题 token）与路由
│   ├── ErrorBoundary.tsx
│   └── main.tsx
├── vite.config.ts      # 开发端口 5173，/api 代理到 8080
└── vitest.config.ts
```

## 2. 模块划分与依赖方向

`pages → components → api`；页面不直接 `fetch`，统一经 `src/api`。UI 用 antd 6，路由 react-router 8，接口类型由契约生成（Ruling-13）。会话放 React Context（`src/auth`），不引入额外状态库；
菜单表 `src/menu.tsx` 同时驱动左侧菜单与路由守卫，增减菜单只改这张表。每个菜单项带一个菜单键（docs/03 §5.6 菜单键目录），侧栏按会话信息里的 `menuOrder` 排序（Ruling-57），排序函数与菜单表放在一起。

界面观感与用户端统一（Ruling-21）：保留 antd 与现有页面，只在三处换肤——`src/App.tsx` 的 `ConfigProvider`
主题 token（主色 `#6777ef`、圆角 3、页面底 `#f4f6f9`、字体 Nunito）；`src/layout/AdminLayout.tsx` 改为 250px
白色侧栏 + 115px 主色色带 + 页头；`src/index.css` 调卡片阴影与徽章。取值与 06 篇 §4 的设计变量一致。
登录页（M10 补充改版）与客户门户的登录外壳同一套布局：整页浅色插画背景、顶栏品牌、左侧登录卡片、右侧标语与三条功能亮点、底部版权，窄屏只留卡片；插画是本模块自己的一份 `src/assets/auth-bg.webp`。
系统设置的“订阅”卡片（M10 补充，Ruling-59）：订阅路径前缀可改写或点“随机生成”，旁边写明修改后旧前缀的过渡天数（可设 0–90）与当前旧前缀及其失效时间（只读）。
平台图标与动效同 06 篇 §4（`src/components/BrandMark.tsx`）：侧栏品牌位与登录卡片显示并播出场动效；antd 的加载指示器经 `ConfigProvider` 统一换成图标的步进旋转。
总览、系统设置、菜单顺序用卡片式页面（`src/components/CardPage.tsx`，照客户后台仪表盘）：去掉外层白色内容框，标题栏单独一张卡，内容卡片在灰底上按宽度自动分栏（`.card-grid`、`.stat-grid`），窄屏单栏；表格类页面仍用白色内容框。

菜单分组：我的（总览、公告、教程、共享账号、工单）、节点（服务器、节点）、用户（用户、套餐、邀请码、订阅记录、登录记录）、
交易（流量包、优惠码、充值码、订单、余额流水、充值单、返利、收支统计；套餐的定价在“套餐”页里）、系统（管理员、角色与权限、审计日志、系统设置、菜单顺序、发件记录、账号安全）；
各项随 M3–M8 加入，权限码照旧由菜单表驱动。

M4 页面（docs/03 §5.6–§5.10）：系统设置按分组一张表单整体保存，`mailEnabled` 只读显示并带“发测试邮件”；发件记录只列收件人（已打码）、
主题与状态，不显示正文；公告、教程的正文是 Markdown 源文本，管理端用多行文本框编辑、不做渲染；共享账号的密码只写，查看时单独取一次；
工单在抽屉里按时间顺序列消息，纯文本原样显示。

M5 页面（docs/03 §5.12–§5.17）：金额在接口里一律是整数分，表单按“元”输入、提交前换成分，列表按设置的显示币种格式化（`src/money.ts`），
页面里不做任何金额运算；充值码生成后只在结果框里显示一次明文（可整批复制），列表只有末 4 位，单条“查看”另取并记审计；
调整余额必须写备注；订单、流水、充值单、返利都是只读的分页表，共用一个分页表格组件；收支统计按天列表加区间合计；
用户行上的“切换身份”向后端要一次性票据，再在新窗口打开 `{site.portalUrl}/impersonate#ticket=…`（票据放在 `#` 片段里，不进服务器日志），
管理端自己不保存票据。

M9 页面（docs/03 §5.19、§5.21，Ruling-50）：节点分组下加“链式出口”——全部出口一张表，按归属（平台 / 用户）、用户、关键字筛选；
平台出口用抽屉表单增改（名称、链接只写、备注、分配方式“按节点组 / 指定用户”二选一及对应的节点组多选或用户多选（按用户名远程搜索，Ruling-64）、可用于服务端 / 客户端、启用），表格“分配”列显示节点组或用户，“查看链接”单独请求、关闭即丢弃；
用户出口行上只有停用 / 启用与删除，删除前写明会连带删除几条规则。平台出口的连接参数与用户端同一套填法（表单 / 分享链接，字段见 docs/06 §5 M9）；
编辑时点“修改连接参数”才取一次现有链接（与“查看链接”同一个接口，同样记审计）。原“服务端链式规则”页改为“链式规则”：
加类型筛选，列出顺序、起飞节点（带各自状态）、落地（带类别徽章）与规则状态，只读。

M10 页面（docs/03 §5.2 入站预填、§5.21 延迟测试，Ruling-51 – Ruling-53）：出口表单的协议加 HTTP、HTTPS（HTTPS 多 SNI 与“允许不安全”两项）；
出口行上加“测试”——弹窗里选起点服务器与方式（TCP / HTTP / 真实延迟），显示延迟、HTTP 状态、出口 IP；不通时显示原因大类的中文说明（Ruling-56）与面板的错误原文，结果不保存；
起点列的是启用中的服务器，列服务器要 `server:read`，没有这个权限的管理员看不到“测试”按钮。
入站表单新建时预填：换传输或安全层时把空着的路径、Host、serviceName、SNI、REALITY 目标填上（规则见 docs/03），路径与 serviceName 旁有“随机”按钮；
切到 TLS 时取一次面板的网页证书路径填进空着的证书，证书卡片上另有“取面板证书”按钮，面板没配证书时提示而不报错。编辑已有入站不预填。
REALITY 的“目标”旁有“扫描”，结果显示在输入框下方（可用 / 不可用及原因、延迟、TLS 版本、证书主体）；“查找目标”打开一张按可用性与延迟排好的候选表，
可以改成自己的一组再扫，点“选用”把目标与 SNI 填回表单（docs/03 REALITY 目标扫描，Ruling-54）。
系统设置新增“路由”分组：开关“平台拦截规则”（`routing.blockRule`，默认开），说明里写明开关会让每台服务器重启一次 Xray（docs/03 §5.19 拦截规则，Ruling-55）。
“系统 → 菜单顺序”页（Ruling-57）：分“管理端”“客户门户”两页签，每个分组一张卡，分组与组内菜单项各有上移 / 下移按钮；“保存”写入整张顺序，“恢复默认”保存空列表。客户门户的菜单目录（键、中文名、分组）在本模块留一份，与 docs/03 §5.6 的目录一致；保存管理端顺序后刷新会话，侧栏立即按新顺序显示。没有 `setting:write` 的管理员只能查看。

服务器位置（Ruling-65）：服务器表单的“地区”改为“位置”下拉框（国家，中文名 + 两位码，可搜索、可清空），编辑时旁边有“扫描位置”按钮，扫描结果只填进下拉框、保存才生效；
新建时留空则由后端自动扫描。服务器列表与详情的位置列显示国家中文名。节点目录的“地区”列显示所在服务器的位置，节点编辑表单不再有地区项。
国家码表在 `src/pages/panel/countries.ts`，中文名用 `Intl.DisplayNames` 生成。

总览分析（Ruling-66）：总览页用页签分成“概览”（原有的数字卡与不在线服务器）和“用户 / 流量 / 服务器 / 财务 / 待处理”五个分区，分区按会话里的权限码出现（待处理人人可见，里面各块按接口返回的非空块显示）。
各分区在 `src/pages/dashboard/`，由 `DashboardPage` 用 `React.lazy` 引入：切到哪个分区才下载它的代码、才请求它的接口；时间范围用分段选择（近 7 / 30 / 90 日），服务器分区的在线曲线另有“近 24 小时 / 近 7 天”。
图表用 ECharts（按需注册柱状图、折线图与 SVG 渲染器，`src/components/echarts-setup.ts` 只经 `EChart` 组件动态引入，单独成包、不进首屏包；写法与 user-web 的同名组件一致，两个模块各放一份）。
图表配置集中在 `dashboard/chart-options.ts`：一张图只有一根纵轴，两个系列时带图例，悬停按横轴出各系列的数值；颜色读 `index.css` 的设计变量（`src/components/css-color.ts`）。
类目少的对比（状态、到期、客户端、订单构成、转化）不用图表库，用条形列表 `BarList`（名字 + 横条 + 行尾数值），数值始终以文字给出；金额仍只做显示换算（`src/money.ts`）。

大陆连通检测（Ruling-67）：系统设置加“大陆连通检测”卡片（开关、间隔、是否通知；标题旁显示是否配了令牌，开关上方写明开启后节点地址会发给第三方探测服务）。
检测开着时（接口里节点 / 服务器的 `reach` 非空）节点目录多一列“大陆连通”：结论标签（文字 + 大陆通过数，只测了 ICMP 的注明“仅 IP”），点开看目标、各探测点的结果与“立即检测”（要 `node:write`）；
服务器列表多一列概况（被墙 / 部分不通的地址数，否则“正常”或“暂无结论”）；总览服务器分区顶部是各结论的地址数与有问题的地址表。组件在 `src/pages/panel/reach.tsx`。

## 3. 关键不变式

1. 菜单与按钮按后端返回的权限码显示；隐藏只是体验，鉴权以后端为准。
2. 不在 localStorage 存会话或凭据；会话靠 HttpOnly Cookie。
3. 面板 token 等凭据只写不读：表单可提交，详情页只显示“已设置”。
4. 删除入站前展示受影响用户数并二次确认。
5. 换肤不改页面结构与交互；每次换肤改动后现有测试必须全部通过。
6. “切换为用户身份”须有独立权限码并记审计，界面上始终显示返回管理员身份的入口（M5）。
