# 08 · 联调与测试方案

## 1. 环境约定

中间件：`v2-hub-contract/deploy/docker-compose.yml`（PostgreSQL :15432、MinIO :19000/:19001；`--profile xui` 起 3x-ui :12053/:12054；`--profile sshbox` 起带 sshd 的 3x-ui，SSH :12222、面板 :12056，只给 IT-14 用）。
联调脚本 `v2-hub-contract/deploy/it/`，黑盒（curl / psql / mc），不 import 模块代码，需要模块进程时自起自停。
IT-5 另需能拉到 `metacubex/mihomo` 与 `ghcr.io/sagernet/sing-box` 镜像（可用 `IT_MIHOMO_IMAGE`、`IT_SINGBOX_IMAGE` 换成固定版本）。
**`run_all.sh` 会重置数据库**，不要对着演示中的库跑。
shell 里设了 `http_proxy` / `https_proxy` 时要同时设 `no_proxy=127.0.0.1,localhost`：否则脚本里的 curl 把本机请求发给代理，等面板就绪的循环会被代理的 503 提前放行（IT-14 因此失败）。
脚本里 `$变量` 后面紧跟中文时一律写成 `${变量}`：macOS 自带 bash 3.2 在 UTF-8 locale 下会把中文字节并进变量名，报 unbound variable，而 `set -eu` 加 EXIT trap 时脚本的退出码却是 0，`run_all.sh` 会把它记成 PASS。

管理员分级加固（docs/03 §4 – §4.4，Ruling-95 – Ruling-100）之后，超管必须先开启两步验证、高危接口要在二次验证的有效期内调用。
各用例统一经 `common.sh` 的辅助处理，断言不因此改变：
- `it_admin_login <jar> <用户名> <密码>`：登录并打印 CSRF token；还没开两步验证的超管当场绑定（`totp/setup` → 算验证码 → `totp/enable`），已绑定的带验证码登录。
- `it_admin_totp_bind`、`it_admin_reauth`、`it_totp_code`（python3 标准库实现 RFC 6238）、`it_totp_next_code`：验证码按账号记下最近用过的步长，
  同一步长不用两次（服务端防重放）；利用服务端前后各 1 个步长的容差，连着用两次不用等，再用就等到下一个步长。密钥只记在临时目录，脚本退出即删。
- `it_hub_config <输出文件> [sed 参数...]`：从 `etc/hub-server.yaml` 派生联调配置，`auth.reauthWindow` 改为 `IT_REAUTH_WINDOW`（默认 2h，长用例中途不过期），
  其余改动照旧以 sed 的 `-e` 追加；所有用例都用派生的配置启动 hub-server。IT-17 测过期时另派生一份短窗口的配置并重启一次。
- `it_admin_cli <子命令> <用户名> [标准输入]`：经 `make` 调 `admin-create` / `admin-owner-set` / `admin-totp-reset` / `admin-password-reset`。

## 3. 联调流程（个人 + agent 模式，每个里程碑结束时跑）

1. 对齐 tag、`reset_db.sh`、起全套服务。
2. 跑 `run_all.sh`：已绿用例全部回归 + 本里程碑新用例。
3. 新发现的问题先固化为 IT 用例（能复现才算），再开 issue。

## 4. 缺陷定位速查

| 现象 | 先查 | 大概率 |
|------|------|--------|
| 前端显示“后端不可用” | `curl 127.0.0.1:8080/healthz` | hub-server 未启动，或 Vite 代理端口不对 |
| 生产首页 404 | `mc ls hub/web-admin` | 前端未发布到 MinIO，或桶未设匿名只读 |
| reset_db 报连接失败 | `docker compose ps` | postgres 容器未起或 `.env` 缺失 |
| `/readyz` 返回 503 | hub-server 日志 `readiness check failed` | `HUB_DATABASE_URL` 未设或库不可达 |
