# 08 · 联调与测试方案

## 1. 环境约定

中间件：`v2-hub-contract/deploy/docker-compose.yml`（PostgreSQL :15432、MinIO :19000/:19001；`--profile xui` 起 3x-ui :12053/:12054）。
联调脚本 `v2-hub-contract/deploy/it/`，黑盒（curl / psql / mc），不 import 模块代码，需要模块进程时自起自停。
IT-5 另需能拉到 `metacubex/mihomo` 与 `ghcr.io/sagernet/sing-box` 镜像（可用 `IT_MIHOMO_IMAGE`、`IT_SINGBOX_IMAGE` 换成固定版本）。
**`run_all.sh` 会重置数据库**，不要对着演示中的库跑。

## 3. 联调流程（个人 + agent 模式，每个里程碑结束时跑）

1. 对齐 tag、`reset_db.sh`、起全套服务。
2. 跑 `run_all.sh`：已绿用例全部回归 + 本里程碑新用例。
3. 新发现的问题先固化为 IT 用例（能复现才算），再开 issue。

## 4. 缺陷定位速查

| 现象 | 先查 | 大概率 |
|------|------|--------|
| 前端显示“后端不可用” | `curl 127.0.0.1:8080/healthz` | hub-server 未启动，或 Vite 代理端口不对 |
| 生产首页 404 | `mc ls hub/web-admin` | 前端未发布到 MinIO，或桶未设匿名只读 |
| reset_db 报连接失败 | `docker compose ps` | postgres 容器未起或 `.env` 缺失 |
| `/readyz` 返回 503 | hub-server 日志 `readiness check failed` | `HUB_DATABASE_URL` 未设或库不可达 |
