# v2-hub-server · 任务与边界

> 负责人：@xiaoclux。v2-hub 唯一后端：管理端 / 客户端 API、订阅端点、面板聚合与下发任务。端口 8080。规格：docs/04-详细设计-hub-server.md、docs/03。

## 职责范围（这里做什么）

- Web 层（`internal/api`）：`/api/admin`、`/api/user`、`/sub`、`/healthz`，参数校验、鉴权、CSRF、限流。
- 业务层（`internal/service`）：管理员 / RBAC、服务器、节点、用户、套餐、授权、链式代理。
- 通用层（`internal/manager`）：面板 Provider 抽象（`manager/panel`）与 3x-ui 实现（`manager/panel/xui`）、订阅渲染、加密。
- 数据层（`internal/dao`）：PostgreSQL 访问，表结构以 `contract/deploy/init.sql` 为准。
- 后台任务（`internal/job`）：健康检查、入站同步、流量汇总、下发对账。

## 接线约定（项目决议，违背即返工）

- 对外：HTTP 8080；响应信封与错误码见 `contract/hub-api.yaml`；会话 Cookie + CSRF 头。
- 依赖：PostgreSQL（`HUB_DATABASE_URL` 环境变量）；3x-ui 面板经 Bearer token 调 `/panel/api/*`（基准 `contract/upstream/3x-ui/`）。
- `service` 只依赖 `manager/panel` 的接口与中立模型，不得出现 3x-ui 专有路径和字段（Ruling-8）。
- 配置：`etc/hub-server.yaml` 入库；凭据（数据库口令、加密密钥、面板 token）只从环境变量读。

## 边界（这里不做什么）

- 不 import 前端模块代码；只读 `contract/` 里的契约文件。
- 不转发任何代理流量，只做控制面（Ruling-4）。
- 不自动建表：表结构改 `contract/deploy/init.sql` + `migrations/`。
- 不托管前端静态文件：前端产物在 MinIO，由 Caddy 分发（Ruling-6）。
